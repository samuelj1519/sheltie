# 产品路线图

本文保存尚未立项的方向和实际触发条件，不描述当前能力。当前产品以[规格](spec.md)和[发布记录](releases/README.md)为准；C004–C008 的完整候选方案由[change 索引](changes/README.md)进入。模型能力或项目规模的预测不决定当前接口。

## 1. 下一阶段目标

用户把一件有明确标准的工作交给 agent，能够以更少的人工投入取得可检查、可追溯、可接续的成果。先做已有本地验收条件的代码库变更，继续保持 Workbook 业务方法与通用引擎分离。单宿主、单 agent 路径必须有价值；更多角色和控制机制由实测问题触发。

C004 把固定候选、实际工具报告、普通返工、接续材料和明确结果放进一条闭环。C005 只补确有需要的执行资格撤销；C006 只处理明确结果的外部副本。C007 比较固定模板编写体验；C008 只在真实必需宿主资源出现时预检。当前均 proposed/not_run，没有因本文成为采用事实。

| 顺序 | 先回答的问题 | 不成立时 |
| --- | --- | --- |
| 编写与摩擦实验 | 固定方法和冻结输入是否比认真配置的原生流程省事？ | 改模板或停止，不先做生成平台 |
| 完整核心闭环 | 工具实际检查、候选关联与结果入口是否减少核对和返工成本？ | 收窄范围，不以状态机通过证明用户价值 |
| 显式替换或导出 | 已有恢复材料/结果位置是否仍存在实际缺口？ | 保持现有能力，不添加额外生命周期 |
| 自动驱动、核心准入或自由图 | 真实重复问题是否超出前述机制？ | 留在路线图，不预写整套接口 |

## 2. GF-20 宿主资源与安装

当前 GF-28 只声明需要的宿主资源，引擎不检查宿主也不安装。能读文件解决的材料继续用 `resources/` 冻结输入；真实需要 skill、命名 agent 或 MCP 的场景先做 [C008](changes/proposed/C008-dependency-readiness/README.md) 单宿主外部预检。

核心准入只有在外部预检重复证明有收益时才立项；须先定实际执行目标绑定、权威观测来源、未知政策、检查/记录/重检查入口。缓存和有效期不是默认要求。没有真实资源使用，不以人工夹具采用产品化。

安装是另一项决定：引擎不写宿主配置，安装实现不得进入引擎进程。确有安装需求时，人授权独立工具，核同名来源、冲突、自己管理的资源范围、卸载与失败停止。宿主plugin目录、引用计数、vendor副本、`.wb`打包与第二宿主适配由实际分发场景决定，不在未验证需求前固定一揽子机制。

## 3. GF-21 版本提醒与延续

同一冻结 Workbook 下的会话重开已经可以用状态卡、任务书和产物继续；C004 完善只读 handoff。C005 的显式替换用于撤销旧 Attempt 的正式提交资格，不等于版本升级或隔离旧进程。

只有真实用户需要在新 Workbook 版本下接续旧产物时，才设计 `continuation/v1`：列出原件身份、引用、缺失和授权边界，由新 Workbook 普通节点判断适配。引擎不热改已运行的图、不从简介推断兼容，不自动迁移旧数据。版本提醒只在已有实际多版本使用时补，不先做会话池。

## 4. GF-22 隔离与权限

本地临时快照只分开工作目录，不提供安全隔离。若任务确实需要约束候选程序、协调者或全部可达工具的文件、进程、网络与凭据权限，单独立项：选一个真实后端，逐项资格验证合法例、越权负例、继承和失败停止。已选择的保护不自动降级，模型自报不成为隔离事实。

不从“代码agent可能出错”直接推出通用容器平台；不从一个平台的成功外推另一个。后端、OS和宿主边界固定后再定节点声明和用户策略接口。

## 5. GF-23 MCP 与多宿主

现有 CLI 足以作为接入基线。C004 的只读 handoff 与 C005 必要时的显式替换，分别核实际宿主续接，不复制宿主的上下文压缩或内部工具循环。

只有命令调用摩擦、参数错误或交互成本的实际数据说明 MCP 有增益时，按公开协议封装工具。描述与指令有界、版本化；每个宿主分别验证调用、取消、恢复和授权，不加宿主专用业务逻辑进入内核。

## 6. GF-24 成本计量与自动驱动

先在各实验报告人工活动、模型/工具墙钟、可观测usage、实际付费和质量，不用模型自报、缺失usage或Attempt时长估算token。跨Work聚合优先组合只读stats，不建设第二状态库。

无人值守自动等待和跨宿主切换只有在响应等待确为主要成本时立项。驱动只执行冻结政策允许的动作，不能把唯一next当授权；门槛批准不自动生成。须实际验证错误来源、未知、共同额度池、付费边界、进程停止和总尝试预算。人工暂停不因等待时间永久报废Work。额度观测、路由和预算先做一个真实入口，不建CLI适配器农场。

流水日志若确有分析需求独立保存，不反向推进Work。自动改进 Workbook 始终由普通方法产出建议、人确认新版本，不让统计自动改图、标准或门槛。

## 7. GF-25 并行草稿

只有真实任务表明顺序执行或宿主原生并行无法满足效率与隔离需要时，才讨论多个current。先测多个独立草稿与普通选择节点；胜出是协调者的内容判断，不变成内核业务状态。不同时建设消息总线、常驻会话池或通用调度器。

## 8. GF-26 自由图与动态展开

[C007](changes/proposed/C007-pre-run-workbook-generation/README.md)先测固定模板、说明与任务输入。固定阶段里的 agent 可以自主细分工作，不要求每个代码子任务成为图节点。模板不能表达的真实任务单独记录。

运行前自由生成图只有在上述不适配重复出现时立项；检查器必须明确结构范围和映射真实性边界，所有检查/确认/安装读同一冻结副本，不用摘要冒充用户授权。运行中展开再单独要求明确槽、继承、有限预算和真实需求，不用它解决已有回环可以表达的任务。

## 9. 其他按需方向

- 机器推进约束：只有真实协调者反复无视工具证据造成错误完成时，才设计闭集事实约束；不解析自然语言审查，不引入第二业务状态机。
- 审查账本与严格身份：先用普通审查/复核和冻结报告；持续发现归属问题或需要可验证分离时，再确定受信来源和预授权解决路径。普通修复不逐项找用户批准。
- 可携带代码：C004先交完整commit及报告；需要搬离原仓库时，另定patch/bundle/archive输入闭包，不能把commit引用当成管理根内文件。
- 清理与归档：只清能证明归属的数据，保留真实产物和必要历史。控制文件、请求快照、审计与文件效果各有职责，不能为精简合并成目录存在性判断。
- 多用户与认证：只有真实协作需要时采用；同OS账户下的声明与gate记录不提供独立身份认证。

每个方向只有经过需求证据、完整提案、人采用、上游同步、实现和验证才成为当前产品。复杂机制先判断它是否承担不可省略的真实义务；能用一个明确接口与普通Workbook完成，就不提前建设平台。
