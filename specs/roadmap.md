# 路线图：MVP 之后

本文保存尚未立项的产品方向。每一项写清为什么推迟、什么时候立项、已经拍板的决定。满足条件后先创建 proposed change package；人采用并更新上游规格与合同时，才进入 active plan，不倒逼当前实现扩大范围。

## 1. 为什么先做这么小

[宪章](constitution.md) §7 说模型越强引擎越瘦。MVP 只做长期一定保留的那几件事：状态、合法边、不可变产物、门槛、上限。先用三份样例 Workbook 证明这几件事真能给协调者省心，再谈其他。这也符合 OpenAI 与 Anthropic 官方指南的第一条建议：先把单 agent 加工具做扎实，再加编排层。

## 2. 条款

### `GF-20` 宿主资源安装工具与就绪检查

**做什么。** 第二个二进制 `sheltie-installer`，把 Workbook 在 `requires` 里声明的 skill、subagent、MCP 装进协调者与工作 agent 的宿主配置，并能卸载。引擎侧加就绪检查：`work start` 与 `attempt begin` 时对照宿主实际安装情况，缺就 `blocked(resource_missing)` 并报告缺什么。分工链固定：**引擎检查并通知 → 协调者请求用户授权 → 安装工具执行**。缺授权停在动作之前。二进制自身与 Workbook 的本机生命周期已在 MVP 的 `self` 与 `workbook` 命令组里（`GF-17`、`GF-27`），不属于本条。

**已拍板。**

- 安装动作永远不在引擎进程里发生（`INV-3`）。引擎与安装工具通过请求文件通信。CI 门禁：引擎二进制的依赖树不含安装实现 crate。
- 资源身份是 `kind + name`（[Workbook 合同 §2](contracts/workbook.md)）。去重与冲突规则：

| 情形 | 处理 |
| --- | --- |
| 两个 Workbook 要同名资源，宿主没有 | 装一份，登记两个引用者。引用计数归零时提示可删，不自动删 |
| 两个 Workbook 要同名资源，`digest` 不同 | 拒绝第二次安装，报 `RESOURCE_CONFLICT`，让用户决定。不搞后装覆盖 |
| 宿主里用户自己装过同名资源 | 视为已满足。Workbook 给了 `digest` 且不符时报告差异，仍不覆盖。安装工具只碰自己登记过的东西 |
| Workbook 带 `vendor/<kind>/<name>/` 兜底副本 | 只在宿主缺该资源且 `source` 不可用时使用；不改变身份与匹配规则 |

- 宿主里的落点是一个 Sheltie 托管的 plugin 目录（Claude Code 这边是 `~/.sheltie/host/claude/` 内一个 plugin，含全部已装 skill 与 agent，向宿主注册一次）。用户自己的 `~/.claude/skills/` 不动。Codex 那边到时按其机制另定。
- Workbook 打包为单文件 `.wb`（受限 tar + zstd）与 `workbook add <file.wb>` 一并在此立项。

**为什么推迟。** MVP 的三份样例只用 `resources/` 输入，没有 `requires`。装 sheltie skill 本身一次手工 `cp` 即可。就绪检查需要知道每个宿主把资源放哪，这是宿主适配知识，不该在没有第二个宿主前固化。

**立项条件。** 第一份带 `requires` 的 Workbook 出现。

### `GF-21` 版本提醒与延续

**做什么。** `work status` 发现同 id 有更高版本 Workbook 已装时提醒。旧产出想在新版本方法下继续时，用一份**延续档案**（`continuation/v1`）当新 Work 的起始输入：档案的完整性节列出全部原件引用与缺失，自然语言简介只是给人读的，不参与核对。评估兼容性是新 Workbook 里的普通节点，引擎不热升级定义、不推断兼容。

**为什么推迟。** 没有第二个版本之前谈不上延续。`workbook add` 新版本与 `workbook list` 标最高版本已在 MVP，提醒只差一行输出。

### `GF-22` 隔离与权限求值

**做什么。** Node 可声明执行环境要求（文件、进程、网络、工具、凭据、资源上限）；用户策略设上限；后端探针报告实际能力；三者求交后才创建环境。至少一个真实后端（候选：Apple container、Docker sandbox、Lima、Tart）通过「合法例 + 越权负例」资格验证后才宣布可用。

**已拍板。** 隔离是节点级声明；已选中的保护不能自动降级；「已隔离」不能由模型或宿主自报；资格分项取证，一个后端的结果不外推到另一个；操作系统沙箱不保证模型不受提示注入影响。协调者、作者、审查者、候选代码与全部可达工具要一起纳入保护关系。

**为什么推迟。** 这是一整套独立的产品能力（策略文件、后端适配、资格测试），与状态机正交。MVP 的三份样例都不需要隔离。

### `GF-23` MCP 接口与多宿主

**做什么。** 把 [协议](contracts/protocol.md) 的每个操作封装成 MCP 工具，工具名 `sheltie_<group>_<verb>`，参数与 `--json` 一致。宿主目标：Claude Code、Codex。每个宿主分别验证委派、并行、取消、恢复能力。

**已拍板。** 工具描述与系统说明版本化并封顶字节数；新增一句必须配一条质量判据。宿主差异由 skill 文本吸收，引擎不长出宿主专用逻辑。

**为什么推迟。** Claude Code 与 Codex 都能直接跑 CLI，skill 教会协调者调 CLI 就够用。MCP 是体验优化，不是能力缺口。

### `GF-24` 成本计量与门禁

**做什么。** 三栏计量脚本：wire 操作数与字节；宿主观测到的模型 usage（不是模型自报）；模型轮次数与历史重发字节。每栏配一条质量判据（交付正确率、产出合同有效率、收敛轮次）。相对固定基线回退超阈值时阻断交付。

**已拍板。** 两本账分开：Work 状态只存有界摘要与文件指针；流水日志独立追加，全量记协调者与工作 agent 的输入输出与 token。引擎不读流水日志做判断。跨多次运行的聚合（「这个 Workbook 二十次运行里 `review` 平均打回 1.8 次」）用 `work stats --json` 逐个 Work 取再合并，不新建表。想让「读多份 `lessons.md`、改 Workbook、出新版本」也由 agent 做，写一个普通 Workbook `workbook-evolve`：输入是若干 `lessons.md` 与当前 Workbook 目录，输出是新版本的 diff 与说明，人审节点在最后；引擎不知道它在演进什么。

**为什么推迟。** 先要有真实运行数据才有基线。

### `GF-25` 并行草稿与单写者选择

**做什么。** 多 agent 并行做同一件事的唯一合法形式：N 个草稿节点各自 Attempt，一个「选择」节点用自然语言写出胜出者，被选中的产物沿原来源向下游流动。需要引擎支持同时多个 `current`（今天只有一个）。

**已拍板。** 不做通用消息总线，不做常驻会话池，不把「胜出」当系统事实。

### `GF-26` 动态展开模板

**做什么。** Workbook 内预登记模板，运行时按有界参数展开为普通节点集合（例如按任务清单生成 N 个「实现 → 验证」对）。

**已拍板。** 模板语法只是推荐的固定写法，不是 DSL：不求值、不脚本、不条件宏，绑定点闭集。展开上限 256 节点、深度 1。

**为什么推迟。** `workbooks/spec-dev/` 用「`implement` 与 `verify` 之间的回环，一次一个任务」表达了同样的事，靠 `max_visits` 限界，不需要展开。只有当任务之间需要真并行时才需要模板。

### 其他保留决定

- **机器路由。** 若将来某类节点确实需要按结构化结果自动选边（例如按 `exit_code`），加一个显式 `conclusion = "machine"` 的节点类型与闭合表达式子集。默认永远是协调者选边。
- **人类多用户。** 需要「独立真人」时，缺认证能力的配置直接拒绝，不让同一操作系统用户换名字过关。
- **`work clear`。** 只清能证明归属且可清理的运行数据，产物永远保留。
- **导出。** 格式独立版本化（`export/v1`），自描述原件闭合、缺失与可重演范围。

## 3. 按模型能力档位的重心

| 档位 | 现实 | 产品重心 | 刻意推迟 |
| --- | --- | --- | --- |
| L0 强助手（现在） | agent 会做很多事，仍会胡说；人要写图与门槛 | 夯实引擎：状态卡、`next`、Attempt、完成 ≠ 通过、骨架预写、门槛与越权两处要人点头 | 多 CLI 农场、会话池、引擎内自然语言判通 |
| L1 准 AGI | 单协调者很强；多 worker 多为并行与隔离 | 薄图富说明；协调者调整任务书成为一等能力；委派合同与预算；延续档案 | 第二套推进状态；把自由任务图做进内核 |
| L2 AGI | 协调者像可靠同事 | 策略与资格平面；导出证据链；安装授权链；计量与预算成控制面 | 用「更聪明的调度」替代合同层 |
| L3 多 AGI | 多个强主体加组织 | Workbook 作可执行宪章；引擎作多方清算所 | 多租户云编排、agent 市场、消息总线 |

口诀：模型每强一档，少做调度，多做宪章与清算。
