# C004 产品方案

状态：`active`；本文定义采用目标，当前产品合同在 T01 同步。实现进度只看 plan。

## 1. 用户路径

方法作者准备固定图、说明、输入输出与必要门槛。任务使用者选择方法，提供本次需求、项目位置与验收说明。协调者按任务书执行，在声明的边上选择返工或继续；引擎不执行检查命令，不解释审查结论。

中断后先查询当前 `work status`，读取当前任务书和输入，再继续原 Attempt。历史请求响应只提供历史事实，不能用其中的 next 代替当前状态。旧执行者是否停止、共享工作区是否安全，由宿主和操作者确认；查询不授予新权限。

流程结束后用户通过 `work result` 找到明确选定的报告和成果，读内容并决定接受、合并或发布。只读查询不代表这些外部操作已经授权。

## 2. 能力合同

| ID | 要求 | 用户可观察结果 |
| --- | --- | --- |
| FR-01 | 状态默认提供当前工作所需指针 | 当前 Attempt、brief、冻结输入、声明草稿路径、next 在文本与 JSON 中一致 |
| FR-02 | 继续与重新尝试分开 | 会话重开不改状态；执行失败按既定 fail/retry；撤销资格按需采用 C005 |
| FR-03 | 结果明确选择 | 只在终点 required 输入/输出允许 result=true；选择 key 唯一 |
| FR-04 | 结果绑定具体版本 | 引用使 Work 成功的终点 Attempt 所绑定输入和封存输出，不重新选择上游最新版 |
| FR-05 | 交付就绪与流程状态分开 | succeeded 但仍有本 Work 未完成文件效果时 final=false，成果集合为空 |
| FR-06 | 来源与结论分开 | 引擎证明文件归属和封存引用，不证明报告中的 commit、退出码或业务结论 |
| FR-07 | 查询保持只读 | 不建管理根、锁或业务目录，不改 request/audit/revision；SQLite 控制文件按 D-039 限定 |

草稿位置只是按冻结输出声明派生的路径，不说明文件存在或字节已经验证。状态默认只列最新 Attempt 所需材料；访问历史以明确的 Attempt 和文件引用为依据，不向协调者投递整段历史正文。

## 3. 最终结果

终点是没有出边的 Node。其输入和输出声明可带 `result = true`，默认 false；选中项必须 required，选中输入/输出的逻辑名不能重复。非终点、可选项或重复 key 在装入时准确拒绝。

`work result` 对任何可读取 Work 返回当前状态。只有 succeeded、门槛事实有效且本 Work 的已提交文件效果全部完成时 final=true。其他情况 final=false、artifacts=[]；不把取消结果或草稿包装成交付。

final=true 可以有空选择。引擎明确显示“未声明最终成果”；方法作者修订新方法，不能从目录名、最近摘要或报告正文推导选择。结果展示的是已封存引用；读取报告内容或复制原件时仍须检验字节，C006 承担其可信读取与消费合同。

## 4. 固定代码方法

最小方法是 implement → review → deliver，review → implement 是显式返工边。实现节点内部调查、规划、改代码、运行项目检查；review 节点独立读取候选与报告并判断；deliver 节点整理成果。方法风险不需要独立审查时，作者可以采用两步图。人工 gate 只按实际授权需要声明，不因方法叫代码开发就自动增加。

每次任务提供 task/project；task 同时承载目标与验收标准，project 提供项目位置和检查前提。稳定方法说明随 Workbook 冻结，任务目标与标准用 start 输入冻结。实现/审查报告写明实际候选、工具原文位置、未检查条件和实际失败；这些是报告内容。终点显式选择 change、review 和 delivery 等所需文件。图合法不证明这些报告关系正确，协调者和独立质量审阅负责内容核对。
