# C008：按真实需要验证单宿主只读预检

状态：`completed`
目标版本：`不进入产品 release`（是否保留外部工具由真实证据决定）
兼容性：不改 Workbook、Flow、Store 或公开操作；不建设兼容层
基线：`75b81ebed655693844ae417bb7d501a1b12a4387`
Owner：`Codex /root；任务作者与独立Reviewer`
权威性：本轮仅前提核对与授权延期交接；探针机制not_adopted，原观察/价值not_run

## 产品目标

当真实任务必须使用已声明的宿主资源，而且重复人工核对已造成可观察负担时，用一个只读外部探针缩短开工前确认。不替用户选择或安装资源，不把「存在同名文件」当成「宿主会使用声明对象」，不承担执行中的持续就绪保证。

本方案先确认问题，再做最小工具。没有真实需求时保持 `not_adopted`，所有机制和价值实验保持 `not_run`。现有 `workbooks/` 与 `examples/` 没有显式 `requires`，不为启动实验人为添加宿主依赖。

## 采用条件

1. C007 自然事件或近期真实任务给出 Workbook、Flow、Node 的明确必需资源及作者确认；普通 `resource.*` 文件不算宿主资源。
2. 同一目标宿主存在重复人工核对或可复核的依赖摩擦，能说明一个小探针预期减少什么活动。
3. 已取得该固定宿主版本的查找、选择和可观察身份规则，以及用户授权的只读范围；不能解释的项预先记 unknown。
4. 人确认准备与维护预算、真实观察范围和保留工具的最低收益。缺任一项不启动脚本开发。

## 范围

- 一个宿主、一个固定版本、一个真实资源目标及实际重复核对事件。
- 复杂模型或有经验作者完整制作极小 Python 探针、必要 fixtures/tests 和 runbook；独立 M1 先审机制，简单模型或初级开发者再按冻结手册记录真实对照。
- 把存在、选择和身份分开观察，输出逐项 `matches / mismatch / unknown` 及证据。
- 人工核对与脚本核对使用同一声明、环境和范围，统计准备、维护、复核及误报成本。
- 不创建多宿主 adapter trait、状态库、TTL 缓存、准入门禁、自动重试或使用证明。

本实验不依赖 C004–C006。C007 可以提供自然问题与声明，但其完整任务对照不等于 C008 的独立价值证据。

## 成功判据

1. 真实对象和宿主规则在开发前固定；探针没有把搜索范围不足、选择不明或身份解释缺失写成确定结果。
2. 正反 fixtures 核机制，真实观察核实际判断；两者分别记录。
3. 探针调用不写 Work、Store、宿主配置或任务工作区，不执行 skill/MCP、不联网或安装。
4. 全部结果可追到获准只读资料；人为缺失或遮蔽只在临时 fixtures 中发生。
5. 结论按冻结预算和真实净成本决定保留外部、改善说明、停止或提出另一个明确范围；一次 matches 或 fixture PASS 不自动产品化。

本轮归档不表示条件probe已实现或原实验通过。补原真实目标/host规则/摩擦/预算后由人决定正式机制采用，按runbook追加，不清洗本轮缺项或历史证据。
