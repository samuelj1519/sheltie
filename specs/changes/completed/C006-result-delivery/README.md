[C004](../../completed/C004-verifiable-delegation/README.md)让使用者找到明确成果。用户确实需要可编辑的文件副本时，本方案把全部已选最终 Artifact 复制到授权父目录下的一份新目录。所有字节核验完成后才原子发布整份副本；失败重做新副本，不建立逐文件恢复系统。

## 产品目标与范围

降低取得正确副本的操作和核对成本，同时保留明确来源、不覆盖现有文件。结果选择只来自 C004。代码仓库和 commit 仍由宿主工具处理；commit、检查结论等若存在于成果报告中，只按原报告字节复制，不升级成引擎核实事实。

实施范围为一个小型外围 Rust 二进制 `sheltie-export`，以及引擎读取指定 Artifact 字节的只读入口。引擎仍只写管理根；导出器只写本次显式授权的目标父目录，不直接读写 Store、不推进 Work。

不建设请求账本、UUID 恢复、锁文件、逐项续传、回执写回、自动覆盖、后台同步、双二进制升级平台或代码仓库复制。独立工具的开发构建与临时目录验证足以完成实施；对外分发另走发布治理。

## 采用条件

1. C004 的明确最终结果已验收，`work-result/v1` 成为唯一选择来源。
2. [C007 共同体验实验](../../completed/C007-pre-run-workbook-generation/README.md)或真实使用证明用户需要文件副本，且人工复制和核对有值得消除的成本。仅需要结果指针或 commit 引用时不采用。
3. 人指定 Owner、独立 Reviewer 与支持平台。首个支持平台为当前发布平台 `aarch64-apple-darwin`，必须实测整目录原子不替换发布。

本方案不依赖 C005 或 C008。已移入 `active/`，T01 先同步上游合同；实现和真实使用按 plan/validation。开发授权不代表已发生真实复制摩擦。

## 成功判据

- 只复制 `final=true`、无待完成效果的结果集合；不猜最后输出或扫描管理根。
- 每项源字节经引擎同句柄核验，导出器独立核 size/sha256 和进程退出码；全体通过才发布目录。
- 目标只增一份完整新副本；已有目标、软链、硬链或目录竞争均不造成覆盖。
- 中断不留下被称为完成的部分成果；发布后同步失败和进程被杀如实报告，不自动接管残留。
- 成果、来源清单和实际字节相符；副本随后可编辑，不承诺持续一致。
- Work、Attempt、门槛和请求历史不因复制变化。真实使用分别记录找结果与复制收益，不混算 C004 的价值。

## 实施分工

复杂模型先确定全局接口和阶段 oracle，完整实现高风险原语，交独立复杂模型审实现准备。简单模型或初级开发者按固定接口完成纯业务与接线，再按冻结手册验证真实使用；独立复杂模型最后核完整结果。分工只服务本方案的实际风险，产品范围不变。
