## 要解决的问题

同次查询重复组装状态与统计，Store 重复检查同一连接，pending 清理有不可达分支，响应和 Attempt 交付组装重复。测试存在重复初始化、复制与原件快照工具，部分负例重复运行完整方法流程；当前文档还混淆历史与限定验收范围。

## 成功判据

- 文本、JSON、历史 brief/stats 与响应的字节和字段保持；合法操作、错误优先级、事务与文件效果顺序保持。
- 删除不可达分支，复用同次计算和同一已核载荷；不减少不同时间点的身份、同步或恢复校验。
- 每个合并或退休测试有明确的后继断言；独立期望和不同入口、故障窗口保留。
- 受影响消费者与完整工程门禁通过，独立审查确认范围和行为；原真实价值、宿主与发布缺项保持原结论。

## 范围与入口

按 [plan.md](plan.md) 实施，文件范围见 [tasks.toml](tasks.toml)，测试处置见 [test-disposition.md](test-disposition.md)，验证和独立结论分别见 [validation.md](validation.md)、[review.md](review.md)。负责人具备完成耦合重构的能力，直接使用既有独立测试；不制造空骨架或人为失败。

Workbook 读取先复用同一已核请求的解码值。跨时间读取合并、批量生命周期索引、跨请求缓存和 filesystem 大范围重构不在本轮范围；目前只有静态重复成本，没有性能瓶颈测量。产品状态、格式、冻结字节、门槛与行政替换语义均保持。
