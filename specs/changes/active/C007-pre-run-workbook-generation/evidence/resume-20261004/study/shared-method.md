# 两组共用的代码任务方法

状态：技术资产已编写；正式运行 `not_run`。这份说明与 [confirmed-input/](confirmed-input/) 只供 C007 私有实验使用，不是分发 Workbook，也不提供真实任务、预算或参与者。

## 同一份文字

原生组与 Sheltie 组都完整读取下列三个文件，不另写缩略提示替代阶段要求：

- [implement.md](confirmed-input/instructions/implement.md)：实现代码、保存 change/checks 和原始检查。
- [review.md](confirmed-input/instructions/review.md)：未参与实现的执行者审查真实候选。
- [deliver.md](confirmed-input/instructions/deliver.md)：按项目预定方式生成完整可应用 patch，整理最终说明。

每份文件包含下方同字的共有策略和该阶段的完整操作。原生宿主将对应文件原文交给该阶段执行者，并提供相同 task/project 及上游报告；Sheltie 的 [Flow](confirmed-input/flows/default.toml) 绑定相同输入并把对应文件原文放入任务书。宿主已有 skill、提示和脚本可以认真配置，但不得改写或删减本方法、放宽标准；两组配置和维护投入分别记录。

## 共有策略

读取本阶段指定的全部输入，按 `task` 的目标与验收、`project` 的仓库位置、初始候选、权限和检查规则工作。先核对正在操作的独立仓库副本与当前候选；输入不足、权限不符或候选无法对应时停止并记录，不补造任务标准。

只修改本次授权范围。遵守项目原有约定，使用已声明的模型、工具和本地检查；不安装宿主资源，不改宿主配置，不自动 push、merge 或发布。需要新增要求、扩大权限或改变固定方法时停止，交协调者处理，原记录保留。

每份报告第一行写明确结论。报告必须区分实际完成、失败、停止、未知和 `not_run`，指出具体文件、候选和原始证据。检查原件记录实际命令、工作目录、影响结果的环境、stdout、stderr、退出码及对应候选；零退出和自述通过不代替内容审查。未知 usage、费用或时间记为未知，不从 Attempt 统计推算。

把输出写到本阶段指定的目标路径。输入和已提交产物只读；不改旧报告或覆盖旧原件。新检查、重试和返工使用新记录，保留全部已投入成本。报告各不超过 262144 字节，patch 不超过 8388608 字节；达到限额、运行预算或固定次数上限时停止，不通过截掉必要事实或放宽边界取得成功。

阶段内可以合理拆解工作；不得增设额外流程节点。固定路径为 implement → review → deliver，review 可返工到 implement；implement、review 各最多访问 3 次，deliver 最多访问 1 次。每次到达最多失败重试 1 次。真实执行失败才记失败；审查建议返工仍是一次正常完成的审查。协调者依据报告选择下一阶段，执行者不自行判断引擎状态。

日常 review 与最终独立质量盲审是不同动作。deliver 默认不设门槛；流程外用户接受、独立质量审阅分别由真实参与者完成并计时。不得把 Work 成功、产物封存、门槛批准或命令退出 0 记成最终质量合格。

## 输入与产物

`task` 由真实任务提供者固定目标、验收、必要拒绝/边界和使用说明要求。`project` 固定真实仓库与两个独立初始副本、初始候选、允许修改范围、既有规则与检查命令、环境，以及覆盖未跟踪文件的完整 patch 生成和独立应用检查方法。所有值和权限在正式运行前给出并冻结；未知项仍为 pending，不能由执行者填成已确认。

| 阶段 | 两组相同输入 | 必需报告或文件 |
| --- | --- | --- |
| implement | task、project、可选 previous-review | change.md、checks.md |
| review | task、project、change、checks | review.md |
| deliver | task、change、checks、review | delivery.md、change.patch |

每份报告上限为 256 KiB，patch 为 8 MiB。implement/review/deliver 的访问上限分别为 3/3/1，每次到达的失败重试上限都是 1；原生组也保存并遵守这些计数。审查正常完成但建议返工走 review → implement；实际执行失败才按重试规则处理。访问或重试耗尽时停止记录，不能绕开 Workbook 上限继续计作原运行成功。

终点只选择五个唯一成果 key：`change`、`checks`、`review`、`delivery`、`patch`。前三项是 deliver 开工时绑定的输入，后两项是其提交输出；不从历史或目录猜测成果。代码位于授权独立仓库，检查原件位于运行记录，报告必须能定位二者。本方法没有 `requires`，没有默认门槛。

## 协调与中断

协调者保存阶段、候选、输入、输出、原始命令和计数；原生组使用冻结的已有宿主持久方式，Sheltie 组使用实时 status、任务书和合法 next。两组均保留报告内容由人或 agent 判断的来源，不把工具状态当质量判断。

关闭重开时先停止旧执行者，实际关闭旧会话，再用新会话读取本组自然拥有的固定方法和持久材料。核对同一仓库候选及报告；未完成阶段接续原工作，不创建替换 Attempt，不重复计一次方法使用。没有真实关闭和重开的原件就不记中断收益。实际使用历史、所有助手活动和成本按 [protocol.md](protocol.md) 记录。

正式准入和操作见 [first-use.md](first-use.md)。最终用户接受与独立质量盲审在流程之外单列，任务运行、作者自测和技术 CLI 验证不能彼此替代。
