# C007 规格：完整任务体验实验

状态：`active`；实验 `not_run`。本文定义一次学习目标，不增加引擎行为。

## 1. 产品假设与角色

方法作者准备可反复使用的步骤、说明、检查与失败路径。任务使用者选择方法，提供本次目标和输入，执行必要批准，取得最终成果。两者可以是同一人，但首次准备、每次填写与后续维护分别计入成本。

实验准备、脚本和质量标准由复杂模型或有经验作者完整负责；简单模型或初级开发者只按 M1 审过的 first-use.md 执行和保存真实原件，不临时决定角色、权限或标准。实际参与者的动作与授权不能由记录者编造，结果由独立复杂模型 M2 核。

实验先回答三个问题：同一方法第二次、第三次使用是否省事；真正中断后是否容易继续；最终成果是否容易找到和核对。使用者若仍要反复解释过程或判断当前事实，记录具体原因，不先增加机制。

## 2. 配对与样本

| 组别 | 提供材料和能力 | 执行方式 |
| --- | --- | --- |
| A：原生 agent | 完整固定方法说明、相同任务目标与标准、同型号模型、宿主和环境；可认真配置已有 skill、提示与脚本 | 原生宿主记录上下文、阶段与交付，不调用 Sheltie |
| B：Sheltie | A 组的全部共有材料，加同内容的固定 Workbook 和当前 CLI | 使用冻结输入、任务书、产物封存、状态卡、合法下一步；只有真实授权边界才设置门槛 |

每项任务两组从同一独立初始仓库副本和目标开始，使用独立新会话。模型版本、推理档位、工具权限、既有 skill、仓库规则、检查命令与环境保持一致。原生组专用配置成本和 Sheltie 装入/填写成本均记录，不能故意削弱基线。

三项任务来自近期真实需要：一项小 bug、一项小 feature、一项有自然返工机会的代码变更。它们适用同一方法，目标和质量标准由任务提供者确认；实验过程中不新增任务要求制造返工。选择、排除理由及两组执行顺序在运行前冻结，采用随机顺序或交替顺序并记录。已解决任务不能再次计时冒充新的复用收益；配对副本的重复求解只能作为同任务对照，并披露熟悉效应。

至少同一位任务使用者在每组分别完成三项任务。T01 按 `actor_id × arm` 冻结此前实际使用本方法的次数；每个 run 记录两组此前使用次数和本组实际使用序号。`exposure` 由本组真实历史决定，不按样本编号指定；同方法练习或准备中的实际使用也算历史，不把有经验的操作者标成首次使用。

至少一位未参与方法编写、具备仓库与 CLI 基础的首次读者使用冻结材料；允许统一入门练习，练习成本及其是否增加本方法使用次数单列。换人、助手代办、跨组熟悉度和顺序偏差均记录并计入成本；不连续的操作者记录不能冒充同一人的复用收益。没有真实任务、连续使用者或首次读者时保留对应 `not_run`，不以作者自测替代。

## 3. 中断、返工与完成

两组至少在同一配对任务的同一阶段关闭原会话并实际重开，不把发送一条「继续」消息当中断。重开时提供各组自然拥有的持久材料和同等权限，记录找回状态、核对候选、重复工作及活动时间。停止旧执行者后继续原 Attempt；本实验不采用替换新 Attempt 的提案语义。

自然审查发现的返工单独记录。若正式任务没有发生返工，可以追加预先定义的临时夹具演练，明确标成 `injected`，不计入自然失败或收益；不得修改真实宿主或任务标准制造故障。自然返工不足时如实限定结论。

交付对象是实际代码变更及必要的检查和使用说明。两组同样交付可复核的 patch、明确的候选标识、原始检查输出与最终说明，由独立审阅者按预定标准评价。只有草稿可运行、Work 已终态或检查退出为零，均不等于质量合格。

默认 deliver 不设 gate。只有样本确有不可替代的授权边界时，T01 才冻结该门槛及两组等价的人工动作。最终用户接受和实验独立质量盲审在流程之外分别记录并计时；两者不由 gate 或 Work 终态代替。

## 4. 实验规则

| ID | 要求 |
| --- | --- |
| EX-01 | 所有正式运行共享文字一致的冻结方法和质量标准；`task` 承载目标与验收，`project` 承载项目上下文，两组内容一致；每组合理配置及成本可见。 |
| EX-02 | Workbook 使用当前格式；方法、说明、标准从同一 `confirmed-input/` 副本读，现有引擎负责校验与摘要。 |
| EX-03 | 每次引擎调用显式传专用 `--home`；不默认回落到正式管理根，不需要 self install。 |
| EX-04 | 当前普通检查报告保持执行者报告的来源；不声称引擎已核实 Git 候选或检查过程。 |
| EX-05 | 原始记录只追加；失败重试保留原因和全部成本。正式协议变化后取得的记录属于新协议，不并入原配对。 |
| EX-06 | 未知 usage 使用 `null`；Attempt 耗时与 Work stats 只作事实补充，不换算 token、模型费用或人工活动时间。 |
| EX-07 | 独立质量审阅者不参与方法、任务标准或成果编写；审阅最终内容并遮蔽组别映射。 |
| EX-08 | 实验不安装宿主资源、不修改宿主配置、不自动 push、merge 或发布；任务仓库修改仅限已授权样本。 |
| EX-09 | 使用历史按 actor_id 与 arm 逐次记录，助手、换人和跨组熟悉度可见；只有实际连续使用支持复用分析。 |
| EX-10 | 公共方法准备、每组配置与维护、每次运行及全部助手活动单独归集；公共方法成本在每组比较中同口径计入，在实验实际总投入中不重复。 |

## 5. 结论边界

实验结果可以支持：继续使用固定方法与说明、缩小目标用户、修正文案、提出一个最小产品增量、停止探索或补一个精确实验。结论必须对应实际摩擦及证据，不把所有候选机制同时排入版本。

只有方法编写被证实是主要重复成本，才单独评估模板填写与直接编写的对照。只有真实宿主依赖造成重复人工核对，才进入 C008。共用完整任务样本不能隔离各候选能力的因果效果，也不自动证明通用生成或内核预检有价值。
