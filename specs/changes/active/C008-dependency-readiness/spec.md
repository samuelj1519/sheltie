# C008 规格：观察声明，不建立准入

状态：`active`（本轮条件前检已采用）；探针机制未采用，原机制与真实观察/价值not_run。

## 1. 要解决的问题

只有已声明且实际必需的宿主 skill、命名 agent 或 MCP 才是检查对象。作者确认必需性，当前引擎只透传声明；本实验不从 instruction 自然语言推断依赖，不为了省一次普通文件读取而要求安装宿主机制。

实验采用前必须有重复人工核对摩擦、一个固定宿主、可用只读规则和准备预算。没有这些事实时，只记录触发说明和 `not_adopted`，不制作探针、不人为制造真实样本。

准备与权限、宿主解析、路径边界、脚本和 tests 由 T01 复杂模型或有经验作者完整负责；独立 M1 只核准备/机制，不宣布真实资源可用。T02 简单模型或初级开发者只按冻结 runbook 做真实对照和保存原件，不改政策、probe、fixtures 或 oracle；T03 分析，独立 M2 核真实范围与成本。

## 2. 声明来源

目标是一个当前格式 Workbook 中被选定 Node 引用的 `kind:name`。先确认该 Workbook 已由真实当前引擎校验；探针读取同一固定目录里的 `workbook.toml`、manifest 指向的选定 Flow 及该 Node 的 `requires`，取 manifest 对应的原始资源声明。

只读这一个目标，不重新编译 Flow 或校验整个 Workbook。检查引用、目录或输入身份变化时停止，要求重新确认；探针不能把自己有限解析成功称为 Workbook 合法。`workbook show` 不提供完整 Node 声明与说明，不作为全部内容来源。

资源的 version、digest、source 均使用已存在的 [Workbook 合同](../../../contracts/workbook.md) 语义。MVP 只透传 version；外部探针只有在声明解释和宿主观察都有明确依据时才比较，不按字符串相等猜版本范围，不另发明摘要闭包。

## 3. 观察结果

| 检查项 | `matches` | `mismatch` | `unknown` |
| --- | --- | --- | --- |
| 存在 | 获准范围内找到满足目标身份的候选 | 完整宿主搜索闭包可观察，且确定没有目标 | 仅部分位置未找到，或无法确认搜索闭包 |
| 选择 | 固定宿主规则可证宿主会选中目标 | 同规则可证选中另一个明确不符对象 | 只知道同名候选存在，解析顺序或当前配置不明 |
| version | 有明确版本解释，观测符合声明 | 同一解释可证不符 | 缺元数据、范围语义或可靠版本来源 |
| digest | 声明和观测指向同一明确完整内容闭包，摘要符合 | 同闭包可证不同 | 闭包不明、部分内容不可读或观察可能漂移 |
| source | 明确来源标识可按冻结规则比较且符合 | 可证来源不符 | 安装后无可靠来源，或缺比较规则 |

存在与选择始终分别报告；version/digest/source 只在声明该字段时检查。整个报告只有所有必要检查均 matches 才为 matches；任一可证 mismatch 则为 mismatch；其余为 unknown。报告不执行任何推进、取消或重试操作，协调者或人解释结果。

明确匹配只证明此次、此版本、此只读范围的观察。网络可达性、实际权限、执行成功、持续就绪及本次任务确实使用了资源，不属于本实验保证。

## 4. 边界规则

| ID | 要求 |
| --- | --- |
| DR-01 | 每个检查项附声明、实际观察范围、固定规则与证据；结论不大于已观察范围。 |
| DR-02 | 同名候选存在不等于被选择；没有完整搜索闭包时「未找到」保持 unknown。 |
| DR-03 | 不读取 token、凭据、进程环境或无关私有内容；不能通过越权读取把 unknown 变确定。 |
| DR-04 | source 是声明数据；不执行、不下载、不联网、不安装、不调用 skill、agent 或 MCP。 |
| DR-05 | 探针只读已授权文件和经核实无副作用的资料来源，不修改宿主、工作区、Work 或 Store。 |
| DR-06 | 合成缺失、遮蔽、未知版本与摘要变化只在临时 fixtures；不删除或移动真实宿主资源。 |
| DR-07 | 宿主或声明变化后生成新观察，原记录保留；不建设缓存、有效期或自动重试。 |
| DR-08 | 使用者自报 used 只能单列 reported，不能回改预检结果或冒充原生使用证明。 |

## 5. 产品判断

人工核对和脚本核对读同一声明、环境和范围，记录顺序与既有熟悉度。判断是否省事必须包含规则调查、脚本制作、运行、解释 unknown、误报处理及维护成本。明确缺失时不强行运行任务制造失败；避免损失只能如实报告不能精确估算的反事实。

有真实净收益且问题重复时可以保留一个外部工具；说明不足时先改善说明；未知过多、成本不划算或需求消失时停止。只有外部方案已证实无法满足一个明确产品义务，才另行提出内核行为。实验机制通过不改变 `requires` 的产品含义。
