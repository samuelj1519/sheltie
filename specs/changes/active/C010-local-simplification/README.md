## 要解决的问题

可信加载有两条恒假拒绝分支；同次请求反复计算意图摘要；Workbook 快照有无效赋值；外围工具有未使用退出码映射。purge 枚举与发布收尾存在可局部复用的重复。自更新测试部分重叠。spec-dev 重复审批更正规则，终点没有选择明确成果。

## 成功判据

- 引擎错误优先级、事务、重放、文件观察时间和发布顺序保持；只有确定不可达或无调用者的实现被移除。
- 合并测试保留缺 tag 拒绝后的同 Home 合法更新、可执行位、原件及 tmp 检查；不同入口和故障窗口保留。
- spec-dev 0.2.2 的 scaffold、implement、verify 显式绑定同一共享审批规则；普通审批、显式更正与停止条件保持。
- 终点明确选择 delivery 输入及 lessons 输出；批准前成果为空，批准后引用绑定 retro 的冻结槽，真实 CLI 可以读回原字节。
- 采用闭包通过工程验证和未参与编写的独立审查；工程结果不授净收益、宿主或发布结论。
