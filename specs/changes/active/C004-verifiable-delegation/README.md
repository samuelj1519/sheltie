## 产品目标

让反复使用同一工作方法的用户，在中断后容易继续，并清楚取得本次最终成果。首批用户是已有本地检查、反复执行代码变更方法的仓库维护者；方法作者负责一次准备，任务使用者负责本次目标和输入，两种角色可以由同一人承担。

引擎继续记录执行事实、冻结引用、合法操作、门槛和上限。方法、检查标准、内容判断和返工策略属于 Workbook 与协调者。流程完成、文件封存、检查报告结论分别表达。

## 范围

- 在 `work status` 中提供当前 Attempt 的任务书、冻结输入、草稿位置和未完成文件效果提示，默认不展开尝试历史。
- 终点显式选择成果，通过只读 `work result` 返回具体版本的 ArtifactRef。
- 提供一份最小代码变更方法及使用说明；普通任务在固定阶段内部自主拆解，不把每个代码子任务建成图节点。
- 使用真实任务确认所采用增量的作用，同时检查交付质量与总人工投入。

本方案不执行 Git 或项目命令，不登记原生检查事实，不增加执行观察状态、独立 handoff 命令、结果规范摘要或导出生命周期。代码 commit 和检查结论保留在普通报告内，不因文件封存成为引擎核实事实。

## 采用条件

[C007 完整任务体验实验](../../proposed/C007-pre-run-workbook-generation/README.md)提供主要摩擦证据。若实际材料已经足够，只改善说明或停止本方向。若用户明确需要稳定的最终选择或当前工作指针，也可用同等近期需求材料采用；采用记录必须说明每项能力的真实消费者和验收理由。C007 的实验结论不自动采用本 package。

采用范围只包含明确的通用增量。不为可选的 C005/C006/C008 提前预留字段。原生候选检查由[路线图](../../../roadmap.md)中的独立触发条件决定，不构成本方案前提。

## 成功判据

1. 首次接触项目的使用者能从状态和说明继续当前任务，不依赖作者口头补充；草稿与已封存产物明确区分。
2. 成功终点所选成果来自该终点 Attempt 的具体冻结输入和封存输出；没有选择时明确为空，不猜最近文件。
3. 非成功状态、门槛未批准或文件效果未完成时不展示可交付的最终集合；查询不推进状态或自动恢复。
4. 同源文本与 JSON、严格持久装入、真实 CLI 正反例和所影响调用链通过独立审查。
5. 在新真实任务中报告首次与复用成本、续接解释和重做、最终质量及未完成项；没有净收益或质量下降时收窄，不用状态机通过代替价值结论。
