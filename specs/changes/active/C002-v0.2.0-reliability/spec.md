## 行为目标

1. **请求身份稳定。** Work 与 Workbook 写操作的 request-id 绑定操作、目标和用户参数。相同意图重放返回提交时完整响应；不同目标或载荷拒绝。self 操作明确不支持 request-id，收到时参数错误；不能宣称 rollback 反复调用无副作用。
2. **输入拒绝无业务副作用。** 缺/多输入、非法名字、缺 Workbook/Flow 在序号分配、Work 物化和请求登记之前拒绝。只读命令不初始化管理根。`workbook show` 公开 Flow 的全部起始输入键。
3. **持久恢复闭合。** 提交前失败不产生可见 Work/Workbook；提交后唯一原件受 Store 归属保护，恢复完成文件发布。历史 brief/stats 逐字节恢复；当前状态卡不回退。worker 输出丢失或变更仍明确报错，不从模型摘要重造。
4. **根内文件与身份可信。** 所有管理路径及恢复路径遵守根限制；普通文件检查、限额、摘要与封存使用同一观测对象。已装 Workbook 必须与登记身份/摘要相同；最终冻结副本重新核验。输出与引擎文件分目录。
5. **摘要无歧义。** 路径与内容采用带长度的确定编码，一次 SHA256。新格式明确版本化，不静默兼容旧错误摘要。
6. **状态可用于续接。** 文本/JSON 状态卡提供同等事实；失败原因、产物引用与 next 可用。stats 的受阻累计不会因取消减少，并保留来源边类型。
7. **Workbook 完成真实交接。** sample 的 back 自动绑定意见；spec-dev 保留全 Work 原始基线、每任务基线和批准条件的适用版本，人工升级可返回原工作，单任务检查不误伤其他任务。
8. **交付自包含且可验证。** skill 脱离源码可用；版本更新使用固定发布身份；质量、文档、MSRV 与发布产物绑定同一候选。

## 兼容性候选

目标版本仍为 v0.2.0，但属于 0.x 下显式破坏性修复。新 Store 升 schema；新 Work 使用单一目录布局；需要变更时同步升级 CLI 响应格式。新二进制拒绝旧 Store，不自动迁移、降级解释或清空。保留旧二进制与旧管理根用于旧记录查询；在新的显式管理根启动新工作。

这项方案不声称旧 Work 可以无迁移继续推进。采用前确认是否存在必须延续的实际 Work；若存在，先补专门迁移任务和验证，不临时恢复 LegacyV1/默认字段兼容。任何工具都不得自动删除旧数据。

## 安全与价值边界

MVP 的 gate 强制命令顺序；同用户环境下不提供独立真人认证或工具隔离。主体使用实际 OS 身份记账，用户授权由宿主与协调者交互负责。引擎不写 shell rc，不安装宿主资源。

不新增 MCP、宿主安装器、多用户认证、并行节点、动态模板、业务判定、事件溯源或评估平台。保留三个 crate、同步处理和 SQLite 单一状态。真实宿主、token 与交付质量另做回归；离线测试 PASS 不能替代。
