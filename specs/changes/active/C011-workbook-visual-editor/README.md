## 要解决的问题

Workbook作者目前手写TOML和说明文件，没有可视化创建/编辑入口。第一版让用户在节点画布编排步骤、编辑属性、检查结构并取得可装入的完整副本。

## 成功判据

- 本地网页可新建Workbook、打开本地Workbook目录、增加/拖动/删除节点、编辑显式边与节点说明/输入/输出。ZIP仅作完整新副本下载；解压后再选目录打开，不增加ZIP导入。
- 能编辑现有code-change和spec-dev副本，保留未编辑Flow、声明和参考文件字节；画布位置只在浏览器本地视图保存，不进入Workbook格式。
- “检查”以可信sheltie的公开CLI在本次自有临时Home装入同一份文件为最终结构判定；未知字段和规则错误不被网页自述通过替代。
- “保存新副本”下载完整ZIP，解压后能实际add/show/verify。源码目录、已装版本和Work冻结副本不被工具直接改写。此方式给网页相同的跨平台文件交付入口，不依赖浏览器直接写目录。
- 实际用户完成从零创建和修改已有方法并给出接受/缺陷；技术检查、独立内容审查、真实浏览器操作分别记录。

## 交付与范围

独立Node网页工具位于 `tools/workbook-editor/`，只依赖TOML解析/序列化和ZIP库；不安装到agent、不发布网站、不改变Rust引擎或schema。入口显式指定可信sheltie二进制，只监听127.0.0.1；服务端不接受任意宿主路径或命令。第一版文件总量至多16MiB/1024文件，超限清楚拒绝，不截断。该作者工具范围不改变引擎已有更大限额。

画布是流程边，输入来源单独编辑；资源文件保留但不增加资源管理系统。高级声明折叠显示。无Work执行/监控、云端协作、账户、插件市场或自动注册。

产品依据为规格GF-34和Workbook合同；[计划](plan.md)、[设计](design.md)、[验证](validation.md)、[交接](progress.md)记录各自职责。当前真实用户试用属于C007用户选择的三任务可用性观察，不替原六次公平代码对照或净收益义务。
