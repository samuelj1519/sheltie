# C005 验证

Candidate: `none`

状态：proposal 阶段。全部实验为 `not_run`。本文件先固定实验口径，避免事后调整指标。

## 1. 要回答的三个问题

分开回答，分开报告：

1. **现有交接材料是否足够。** 用现有 CLI、状态卡、产物和任务说明，换一个宿主能否继续同一个 Work？
2. **新增状态机制是否正确。** 执行代次、可恢复等待、分开计数是否按承诺工作？
3. **自动驱动是否减少无人响应的等待。** 用户不在场时，驱动层能否缩短从中断到继续的时间？

问题 1 的答案很好（解释成本很低），不代表问题 3 没有价值：凌晨一点额度耗尽、早上八点才被人看到，解释成本再低，完成时间也多了七小时。

## 2. 第一阶段实验：人工接续（现在即可执行）

用现有合法 CLI 路径执行，不改产品代码。

**能力边界：** 内核修改前，GF-14 只允许非门槛阻塞后取消，现有也没有执行代次。所以这一轮只回答问题 1，不能声称“额度等待与恢复”或“旧执行者提交会被拒绝”已经验证。额度中断用人为方式模拟，报告中标注“模拟中断，验证的是恢复路径，不是真实提供方的额度事件”。

场景（与 C004 阶段 1 共用任务样本）：

| 场景 | 做法 | 观察 |
| --- | --- | --- |
| 工作执行者中断 | 实现做到一半，停止 Claude Code，在 Codex 中接手 | 重新解释量、约束丢失、重做量 |
| **审查者中断（重点）** | 候选已通过机器检查，审查做到一半停止，另一宿主继续审查同一候选 | 已登记的问题是否保留；标准是否变化；是否需要重新解释 |
| 协调者中断 | 协调者停止，用户在另一宿主接手协调 | 接手者能否从状态卡恢复推进；有没有非法操作 |
| 没有合格备选 | 合同要求独立审查，只剩作者可用 | 协调者是否等待或找人，而不是降级为自审 |

审查者中断场景同时检验身份、问题保留、接续和验收四者是否衔接，优先执行。

对照分两组：

- 用户手动换工具、复制背景的实际流程；
- 宿主原生恢复：同一 Claude Code 交互式会话，打开 `autoContinueAtUsageLimit`，等额度恢复后继续（workflow 场景要求 v2.1.271 及以上）。

原生恢复能覆盖的场景，C005 不应声称有增量；实验要分开报告同宿主恢复、跨宿主替换和换资源三种情况。

## 3. 指标

| 指标 | 口径 |
| --- | --- |
| 重新解释量 | 换执行者后，用户为让新执行者理解任务而写的消息条数和分钟数 |
| 约束丢失 | 新执行者违反或遗漏原合同约束、已确认决定或未处置发现的次数 |
| 重做量 | 新执行者重做已完成工作的次数，以及额外的重新验证耗时 |
| 响应等待 | 从中断发生到用户实际接手的时长 |
| 人工分钟 | 用户在接续中花的全部时间 |
| 端到端时间 | 从 Work 开始到交付包产出的墙钟时间 |

人工分钟和端到端时间分别报告，不合成一个评分。每条成本指标都配一条质量判据：约束丢失、最终验收结果（按 C004 的外部审阅）。

## 4. 第二阶段实验：自动接续（第一阶段通过后）

| 场景 | 应观察到 |
| --- | --- |
| 工作执行者额度耗尽 | 驱动层按预授权切换到合格备选，或进入等待 |
| 协调者额度耗尽 | 驱动层接手推进，不需要用户在场 |
| 所有备选共享同一额度池 | 进入等待，不在同一池中循环切换 |
| 额度观测缺失 | 按“未知”处理，不当作充足或耗尽 |
| 主选额度耗尽，备选在冻结的候选集合内 | 直接切换，不修改 Workbook 或绑定，记录实际选择与授权版本 |
| 需要集合外的候选或转入付费 | 停下来请求新的授权版本 |
| 门槛阻塞，`next` 只有 `gate approve` | 驱动层通知用户，不执行 |
| 政策允许的 agent 审查 | 驱动层自动启动审查 |

指标：重新解释量、重做量、无人响应等待是否下降；错误切换次数；政策违反次数（应为 0）；标准降级次数（应为 0）。

便宜模型的分工不必等驱动层：第一阶段即可由用户按固定配置把少量同类任务交给便宜模型，同时记录质量和完整成本（token、实际付费、稀缺额度占用分开记录）。

## 5. 失败路径测试（与用户价值分开报告）

采用并实现后执行。

| 场景 | 应观察到 | 不能出现 |
| --- | --- | --- |
| 旧代次在新代次开始后提交 | 拒收并记录 | 覆盖新状态 |
| 旧执行者无法确认停止 | 交接包写明风险；新执行者使用分开的工作区 | 静默共用可变工作区 |
| 资源不可用多次 | 消耗资源重试，不消耗业务重试 | 业务重试被耗尽 |
| 执行者反复自报“不可用” | 资源重试、切换次数或总等待期限耗尽后找人 | 无限重试 |
| 到达重置时间但没有新观测 | 仍在等待 | 自动恢复为可用 |
| 额度观测缺失 | 记为未知 | 当作零或充足 |
| 原因为“权限或数据政策不允许” | 停下来找人 | 换宿主后继续 |
| 合同要求独立审查，只剩作者可用 | 等待或找人 | 作者自审被当作满足 |
| 审查者中断后由备选接替 | 原发现保留（C004 VD-09） | 发现消失或被覆盖 |
| 驱动层被杀（第二阶段） | Work 可人工接续，状态不分叉 | 状态丢失或出现第二套进度 |
| 实际配置与请求配置不同（第二阶段） | 记录差异，配置版本不变 | 改写已使用的配置版本 |
| 切换到需要付费的执行入口（第二阶段） | 没有预授权时拒绝 | 悄悄切换 |
| 切换到冻结候选集合之外的执行者（第二阶段） | 拒绝，要求新的授权版本 | 覆盖原绑定 |
| 新授权版本生效后领取（第二阶段） | Attempt 关联新版本，旧记录不变 | 旧 Attempt 被改写为新版本 |
| `next` 唯一但政策不允许自动执行（第二阶段） | 驱动层不执行 | 把唯一选项当作授权 |
| 读取 `next` 后、领取前授权或依赖变化（第二阶段） | 领取被拒绝，重新读取 | 按旧状态执行 |
| 宿主返回的失败类别无法映射 | 记为原因未知 | 猜测为资源不可用 |
