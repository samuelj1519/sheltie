# C005 对独立审阅的答复（2026-09-27）

答复对象：[independent-review-2026-09-27.md](independent-review-2026-09-27.md)。本 package 仍为 `proposed`；人工接续、自动接续与失败路径测试仍为 `not_run`。本轮只改本目录内的提案文档，不改根规格、合同或代码。审阅结论（第一阶段保留 proposed 并补交接机制，第二阶段不随 v0.3 自动打包）接受。

## 逐条答复

### 1. 从旧 `running` Attempt 到新执行代次的原子交接（高）

**判断：采纳；问题比审阅所写更具体。**

理由：现行 `next` 在最新 Attempt 为 `running` 时只开放 `submit`、`fail`、`cancel`；要换人只能先 `attempt fail`，而它消耗 `max_retries`（contracts/protocol.md `attempt fail`），直接违反 EX-05“业务重试只在内容失败时消耗”，也把中断误记成执行失败。原 EX-02 只写了“拒收旧代次”，没有结束旧 Attempt 的操作。

处理：

- 新增“取代运行中的 Attempt”（CLI 候选名 `attempt supersede`）：写锁内旧 Attempt 转为新终态 `superseded`，记录中断原因与来源，不计业务重试，计切换次数，同一事务内开放 `attempt begin`；沿用 `work cancel` 不伪造结束的原则。
- 不另设“执行代次”状态。旧 Attempt 结束后，它的迟到提交已由现有 `ATTEMPT_NOT_RUNNING` 拒绝；代次改为 Occurrence 内 Attempt 顺序的派生显示。
- 旧进程写文件：Store 内每个 Attempt 的 `outputs/` 已分开，未提交文件留在旧目录；共享 Git 工作区在引擎之外（INV-3），作为交接条件显示，不作保证。
- 受影响条款加入 GF-11 执行事实闭集的扩充，合同行加入 `attempt supersede`。

修改位置：spec.md §1 表、EX-02、§4、§6；design.md §1、§2、§4（重写）、§10 问题 1；validation.md §2、§5；README.md 成功判据。

### 2. 资源不可用的来源不能混成已观测系统事实（高）

**判断：部分采纳。** 来源字段（EX-03）、上限（EX-05）和恢复条件（EX-04）方案已有；`attempt fail --reason` 也是先例，记下的系统事实是“有人调用了 fail”，不是“原因为真”。真正的缺口在命名与展示：`blocked(resource_unavailable)` 读起来像已确认，第一阶段的恢复方式也未写死。

处理：状态改名为 `blocked(resource_wait)`，按来源显示，模型自报显示“暂停，未核实”，只有提供方通道可称“提供方报告耗尽”；第一阶段恢复只接受用户或协调者发起的获准尝试（关闭 design §10 问题 4）；实验中模拟中断与真实提供方事件分行报告。

修改位置：spec.md EX-03、EX-04、§4、§5；design.md §5、§10；validation.md §2、§5。

### 3. 第一阶段与 C004 的先后要选一条真实可交付链（高）

**判断：采纳。** 交接包的“验证结果”“未处置的发现”来自 C004（design §3），场景 2 依赖 VD-09，EX-07 的独立性依赖 VD-10；“接口定稿”不等于已实现。

处理：保留两种顺序，但写死排在 C004 前面时的承诺：状态卡、产物指针、冻结 Workbook、取代运行中的 Attempt、资源等待与分开计数。C004 来源的字段、独立性判定、场景 2 和 4 标为“C004 采用并实现后启用”；期间不另建发现账本或身份记录。

修改位置：README.md 采用条件与依赖；spec.md §2、EX-01、EX-07、§4、§5；design.md §2、§3；validation.md §2。

### 4. 不要把未知额度视为可切换许可（中）

**判断：前半采纳，后半已覆盖。** EX-11 原文“额度池没有被观测为耗尽”会放行未知，与 EX-10 矛盾。读取 `next` 后到领取前的重核已在 EX-14 与 validation §5“读取 `next` 后、领取前授权或依赖变化”一行。

处理：过滤条件改为“有新鲜观测且未耗尽”；额度未知的候选只能作一次获准探测，计入资源重试与切换次数，记录“不代表额度确认”。

修改位置：spec.md EX-11；validation.md §5。

### 5. 两阶段授权与进度单独闭合（中）

**判断：已覆盖。** README“范围约束”已写两个阶段分别采用；validation §2 已写第一阶段不能声称状态机制已验证；失败路径测试标为采用并实现后执行。未改机制。

审阅在推进建议中指出的冲突成立：README 第二阶段条件中的括注“用户已提出这一需求，所以实际上只剩前一条需要验证”实际取消了实测触发。按人工决定改为：实测无人响应等待且为接续主要成本才触发；用户的离线推进需求作为立项动机记录，单凭它不满足条件。

修改位置：README.md 采用条件（第二阶段）。
