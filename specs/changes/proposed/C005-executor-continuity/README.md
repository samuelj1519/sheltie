# C005：显式替换运行中的 Attempt

状态：`proposed`
目标版本：`待采用时确定`
兼容性：`持久格式与响应格式需版本化；不自动迁移旧 Store`
基线：`17a1647758ceea5ebf637610ab2cdf91589c5218`
Owner：`待采用时指定`
权威性：候选方案；采用前不实施产品代码，不修改当前产品合同。

同一个 Work 已有足够的状态供会话恢复。只有需要撤销旧 Attempt 的提交资格、让另一执行者重新领取时，才需要引擎增加操作。本方案提供一次原子的 `attempt replace`：旧 Attempt 记为 `superseded`，同一 Occurrence 创建新 Attempt 并返回任务书。

## 产品目标与范围

用户换执行者后仍按同一份冻结方法和输入完成任务。替换不伪造执行失败，不消耗业务重试，也不丢掉旧尝试的历史；迟到的旧提交通过正常接口被拒绝。

[C004 的交接视图](../C004-verifiable-delegation/README.md)负责展示状态、冻结输入、候选与证据指针。恢复原会话、协调者重开、等待额度恢复，均优先继续原 `running` Attempt。没有需要撤销的提交资格时，不使用替换；等待本身不新增 Work 状态。

本方案不启动或停止宿主进程，不证明执行者身份，不提供 Git 工作区隔离，不探测额度，不自动选模型。独立审查仍由普通 Node 与协调者安排。自动等待、资源预算和离线驱动属于[路线图](../../../roadmap.md)上的后续方向。

## 采用条件

1. C004 的最小闭环已实现，交接视图能够定位原 Attempt、冻结输入、候选和证据。
2. 实际使用中出现需要撤销旧 Attempt 资格的情况；仅会话恢复材料不足时先完善 C004，不增加替换命令。
3. 人确认格式版本、默认关闭的替换上限和受影响的上游合同。
4. 采用时将本目录移入 `active/`，按实施起点核对代码路径；默认只运行一个 active change。

## 成功判据

- 一次替换同时结束旧 Attempt 和创建新 Attempt；提交前中断不改变业务状态，提交后中断能恢复同一份任务书。
- 旧 Attempt 的迟到 `submit`、`fail` 被拒绝；并发提交与替换至多接受其中一个。
- 替换数与业务失败数分开。替换上限耗尽时整次请求被拒绝，旧 Attempt 仍可继续，不增加只能取消的阻塞状态。
- 同一请求重放返回第一次提交的完整响应和原任务书字节，不创建第二个新 Attempt。
- 真实接续没有关键约束丢失，能够解释哪些成本由交接视图消除、哪些额外收益来自撤销旧资格。未发生真实替换需求时，价值验证保持 `not_run`。
