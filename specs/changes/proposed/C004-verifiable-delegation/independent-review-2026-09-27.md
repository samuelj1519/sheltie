# C004 独立方案审阅（2026-09-27）

审阅对象：本 package 的 `README.md`、`spec.md`、`design.md`、`validation.md`、`review.md`；对照当前宪章、规格、合同与 C002 `plan.md`。本文件只评估尚未采用的方案，不是产品实现审查。C002 仍在实施；C004 的两阶段价值实验和失败路径测试均为 `not_run`。外部依据见 [一手来源笔记](../../../research/2026-09-27-agent-rust-guidance.md)。

## 结论与产品价值

**方向值得验证；当前方案需修改后才能进入采用决定。** 首批用户限定为已有本地验收命令的个人开发者，符合本地工作流引擎的边界。把候选、冻结标准、机器证据和返工关联起来，比单纯增加 agent 调度更可能减少用户反复解释与核对的时间。单用户、同权限下不承诺防伪造或隔离，也符合实际。3 个摩擦探针再做 5–8 个任务的对照，比直接开发整套机制更可行。

价值尚未得到实测。OpenAI 与 Anthropic 都建议从能评估的单 agent 工作流出发，随真实失败增加复杂度；这支持本方案的实验顺序，并不证明 Sheltie 的产品收益。原生组已有 skill、干净工作区和同一验收命令，必须保留这个有力对照。Rust 工程上，纯 `core` 判定、`runtime` 持久化、外围执行器的依赖方向合理；真正的成本在快照执行、故障恢复、Store 格式和多次冷构建。

## 采用前需修订

1. **高：接收规则必须限定可接受的证据来源。** `spec.md` VD-02 记录「验证器取得 / 外部回填」，但 VD-06 只要求必需条件存在有效的 `satisfied` 证据。`design.md` §4.4 又要求协调者回填不能显示为已验证。若接收点只比较结果枚举、候选和规则版本，回填的 `satisfied` 仍可能开启接收出口。应由冻结合同为每个必需条件声明允许的来源与写入方式；接收点校验这个字段，且外部回填不得自称本地验证器结果。合法验证器证据与仅改来源的回填证据应构成一对真实 CLI 反例。这仍只是正常接口约束，不升级为同权限防伪造承诺。
2. **高：明确 `not_verified` 的状态转换。** `design.md` §2 定义了 `failed → back`，`spec.md` VD-03 把未启动、超时、中断归为 `not_verified`，却没有规定验证节点 Attempt、`next`、恢复和重试计数如何变化。当前 GF-14 对非门槛 `blocked` 只允许取消；C005 可恢复等待尚未采用，C004 又可能先实施。应先给每一种验证器故障定义可观察的合法下一步、是否消耗业务重试、上限与停止路径；若依赖 C005 才能恢复，则把它写成实施顺序的硬依赖。不能把环境故障伪装成候选失败来走返工边。
3. **高：决定受控接收点与现有完成语义的关系。** 当前 `attempt submit` 成功后可按 GF-14 使终点 Work `succeeded`；C004 另加「接收」出口和交付包。方案需规定接收是边、专门操作，还是已有终态前的结构条件；证明无机器条件、仅有人工判断条件、审查中断和 `gate` 同时出现时，`next`、Work 终态与交付包用语一致。否则「Work 已成功」与「候选未接收」会被混用。采用时先修改宪章 INV-1/INV-5/INV-6、根规格与协议，再进入 Rust 实现。
4. **中：收窄“冻结验收规则”的可执行承诺。** `design.md` §3.2 c 把脚本、测试、`.gitattributes` 与影响测试选择的构建配置列为受保护路径，但项目可以通过未列出的配置、依赖、环境变量或动态发现改变验收行为。首版应声明冻结的命令、脚本、环境输入与受保护路径的闭合范围，并把超出范围的行为列为已知局限；故障探针覆盖改动受保护文件、未列文件影响测试选择、源仓库并发变化和候选 checkout 不符。不要从「测试运行成功」推出规则未被改变。
5. **中：把 VD-09 设为条件性范围。** 审查发现追加、跨候选延续、用户处置和执行身份三栏会显著增加状态与合同复杂度，还要修订宪章。`design.md` §9 已给出正确的决策点：先测协调者忽视审查与误报成本，再决定是否纳入 v0.3。若探针没有显示净收益，首版只保留来源标注与未完成如实报告；不要因为方案已写全就一并实现。

## 推进建议与验收口径

先完成 C002 的身份、摘要与恢复闭合。随后固定任务样本和原生组配置，跑 3 个摩擦探针；记录冷构建、前提缺失、返工与人工接管各自的耗时。只有证据显示验收闭环带来净收益，才决定 ADR-A/B、Store 格式和受控接收点。采用后按「合同/状态转换 → 证据写入与来源 → 本地验证器 → 真实 CLI 返工与交付」分任务；每个写入路径做正反例、COMMIT 前后恢复、固定候选与不同额外文件的独立核对。对照实验按 `validation.md` 的外部盲审报告人工分钟、质量、错误接收/拒收和未完成率；任何单项结构测试 PASS 都不等于产品价值 PASS。
