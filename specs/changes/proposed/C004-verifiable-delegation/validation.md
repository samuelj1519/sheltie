## 1. 三任务摩擦探针

T01 在 `experiments/samples.md` 登记一个bug、一个小功能、一个预期至少返工一次的真实任务；分别保存仓库、完整基线、需求、条件、实际命令、工具/宿主/模型版本、环境和授权。3个任务合计覆盖一次返工和一次真实关闭重开，注入事件与自然失败分列。

T02使用当前引擎、固定阶段说明和外部脚本，不改产品源码，不假装拥有原生记录或机器推进约束。每次人工解释、核对、处理失败和接管记开始/结束及原因；验证故障、agent失败、标准缺口分别记。缺usage记录为null。

M1回答：主要成本是方法配置、候选/证据核对、接续解释、环境还是最终审阅？拟原生工具与结果入口是否正好解决已观察到的问题？若环境搭建占主导，收窄样本；若现有材料已经够用，删除无增益功能，不把样本缺陷当通用平台需求。只有净收益方向和可执行架构都清楚才进入代码阶段。

## 2. 5–8任务配对对照

正式实验前冻结样本和口径；两组各做同一任务，顺序随机。同一模型/宿主版本、基线commit、验收标准、权限、已有工具链/缓存/服务与等价干净工作区。原生组可以认真配置skill、worktree和脚本，不以脏目录或缺指示压低基线。

外部审阅者在不知道组别时按预先标准审最终diff；Work成功或本地命令零退出都不是外部真值。质量、人工时间和墙钟分开报告，不组合成任意评分。

| 指标 | 口径 |
| --- | --- |
| 人工分钟 | 首次准备/配置、输入、核对、返工、排障、接管及最终审阅；首次与复用分别报告 |
| 质量 | 条件满足数、重大/阻断缺陷、外部不接受结果；不接受任务不能从时间账删掉 |
| 接续 | 新增解释、约束遗漏、重做与重复验证 |
| 未完成 | 上限耗尽、放弃和缺前提，说明原因 |
| 工具成本 | 实际检查耗时含冷构建、模型墙钟、可观测usage/实际付费；未知不估算成零 |
| 标准诚实性 | 非零、未启动、未完整验证、普通审查和gate来源是否分别显示 |

方向判断是所测样本内人工投入有下降且质量不下降；报告逐任务原值和离散程度，不以小样本宣称普遍节省比例。阈值或样本如需改变，先固定新实验，不拿已有结果调口径。C007模板实验可共用真实任务，但它测编写负担，不替代本实验的完整任务收益。

## 4. 里程碑验证预算

M1只审探针输入、事实和架构，不跑产品突变。M2先核状态/来源/锁/快照真实caller，冻结后对新增观察状态与拒绝路径做定向突变并带相关CLI消费者。M3跑一次当前闭包完整工程门禁、结果选择与可信流的必要突变、真实宿主与配对实验。实际inventory、测试组、基线耗时、并发和停止条件在执行前写定；共享期望归组但每ID保留原结果。

既有强制提交门禁依工程规范执行。相同闭包可否复用必须按已采用规则证明，不擅自修改hook或把不同features/fixtures/环境的结果合并。方案静态检查不计入上述机制结果。
