# C004 产品方案

状态：`proposed`。本文完整定义候选行为；当前产品仍以根规格和 C002 完成范围为准。

## 1. 用户路径

1. 用户选一份已批准的固定 Workbook，提供目标、项目位置和本地检查说明。任务说明与检查配置作为 `start.*` 文件按实际字节冻结。
2. 协调者领取任务书，派执行者实现。实现者在已授权的工作区提交候选；引擎不替它写用户仓库。
3. 普通验证节点领取后，协调者调用本地验证入口。工具固定完整 commit，在独立临时目录执行冻结命令，生成实际观察记录。
4. 协调者读报告。检查非零时判断应修候选还是处理前提；超时、未启动或中断不能冒充已检查。按既有显式边和上限返工、重试或停止。
5. 需要审查时，由普通审查节点读同一候选和工具报告。修复后再检查和审查；只有预先声明的 gate、越权、标准变更或无法收敛才请求人。
6. 终点把要交付的输入和输出明确标成结果。Work 完成后，用户读结果视图并决定合并；外部文件复制由 C006 按需提供。

## 2. 最小能力

| ID | 行为 | 保证范围 |
| --- | --- | --- |
| VC-01 | 冻结任务、基线、检查命令和环境声明 | 复用 Workbook 与 start 输入；本版本不能运行中改标准 |
| VC-02 | 实际执行检查并登记原生记录 | 只能由本地工具入口取得，不接受自报来源或退出码 |
| VC-03 | 固定候选和输入身份 | 完整 commit、配置摘要、实际快照摘要和实际工具信息一起记录 |
| VC-04 | 区分执行与判断 | 非零只说明命令没通过；环境与候选根因未知时不猜 |
| VC-05 | 既有返工和重试 | 协调者选边；没有新接收状态、审查状态或发现处置制度 |
| VC-06 | 只读交接材料 | 当前 Attempt、冻结方法、输入输出和记录指针；无完整聊天转录 |
| VC-07 | 明确最终结果 | 从使 Work 成功的终点 Attempt 的冻结引用取，不按目录或自然语言猜 |
| VC-08 | 诚实展示检查情况 | 流程完成、命令通过、审查意见、门槛批准分别表达 |

## 3. 检查支持范围

首版只检查已有的本地普通 Git 仓库和完整已存在 commit。工作树脏文件、未跟踪文件、submodule、Git LFS 外置内容及额外覆盖文件不复制；不满足完整快照条件时明确拒绝或报告缺前提。源仓库只读，不创建 worktree、不修改 `.git`、不提交代码。

命令以绝对程序路径和参数数组声明，不隐式经过 shell。需要项目脚本时，用户显式声明解释器和配置的相对 script 字段；脚本必须来自本次 commit 的受保护文件，执行 cwd 固定为本次检出根，不能指向原仓库或外部脚本。检查有命令级有限超时和有界日志，允许项目已配置的缓存与服务，但必须列明未冻结的外部前提；不承诺完整环境重演或安全隔离。

基线中指定的检查脚本和配置路径必须保持原字节；命中改动就不运行，报告标准发生变化。新增测试可以正常运行，其效果属于所执行命令的完整结果，不声称能从聚合退出码分离既有测试。需要独立验收时，另声明独立命令，不能靠隐含的“新测试不算数”规则。

## 4. 检查事实与合法操作

工具观察是 Attempt 的附属记录，不代替执行状态。完整运行的零或非零退出均可以形成验证节点的成功执行；业务通过与否由协调者读结果判断。未启动、超时和中断列为未完整验证，协调者以 `attempt fail` 在验证节点自己的上限内重试。故障原因不能机械判明时保留未知。

本版本不按检查枚举自动选边或强制关闭任意 Flow 的出口。固定代码 Workbook 规定验证、返工与普通审查路径；最终结果显式带上被交付候选的原生报告。普通接口不能将自报文档提升为原生检查事实；任意 Workbook 成功也不被展示成所有标准都已满足。若实验发现协调者经常无视检查而继续，记录实际比例，再独立决定机器推进约束，不能预先扩成通用接收制度。

每个验证 Attempt 至多登记一次检查批次。未完成批次禁止再次启动；已完成批次通过只读视图查询，重复调用不重跑。确认进程已停止后关闭失败 Attempt，再领取新验证 Attempt。恢复器不得自动执行项目命令。具体长执行协议见 design。

## 5. 接续与结果

`work handoff` 为只读投影：Work/Workbook/Flow 身份、revision、当前 Attempt 与任务书、冻结输入和已封存产物、未完成观察、最近摘要及当前 `next`。未提交草稿单列为未验证路径，不把它变成正式产物。正常重开继续原 Attempt；需要撤销旧执行资格才使用 C005。

终点输入或输出可以声明 `result = true`；终点成功和门槛批准后形成最终结果。普通文档任务返回选定 Artifact；代码任务再由选中的原生检查报告给出候选 commit。结果引用不等于用户仓库 HEAD，不会随着后续编辑更新；改变候选必须重新检查并形成新的结果引用。

缺少原生检查报告时，结果只显示已选文档与“没有机器检查”。存在失败或不完整检查时如实显示，不能因为 Work `succeeded` 改成通过。多个所选原生报告对应不同候选时拒绝构造单一候选结果，并指出冲突。

## 6. 信任与授权

保留 INV-1–INV-7。core 比较闭集结构与引用，不理解报告；runtime 观察文件并持久登记，不理解 Git 或审查；独立工具模块处理 Git 与子进程。真人 gate 仍只记实际 OS 主体，不提供独立真人认证。声明自己独立不等于观测到身份分离。

本地验证不是沙箱；候选代码和引擎可能处于同一 OS 权限域。工作区分离不阻止同权限代码修改控制文件；本方案承诺正常接口的来源与引用约束，不宣称抵抗同权限恶意执行者。超时能尝试终止所持进程组；父进程被强杀后不承诺全部后代已停止，重试前须核实际残留。
