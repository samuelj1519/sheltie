## 产品目标

用户把一件有明确标准的工作交给 agent，用更少的人工投入取得可检查、可追溯、可接续的成果。首个场景是已有本地验收条件的 Git 代码库变更。引擎继续管理执行事实、冻结引用、合法边、门槛和上限；内容判断与修复策略由协调者和普通 Workbook 节点承担。

本 package 形成一条完整链：冻结任务与检查说明 → 实现候选 → 工具实际检查 → 协调者组织返工 → 普通审查（需要时）→ 明确结果。既有 Work/Attempt、输入冻结、重放和恢复继续复用。

## 范围

- 一个固定阶段的代码变更 Workbook；任务细分在普通执行节点中完成，不生成新图。
- 同一候选上的本地检查记录，明确退出码、超时、中断和未验证范围。
- 只读 `work handoff` 恢复视图；继续原 Attempt，不要求先标失败。
- 终点明确选择结果，提供 `work result` 与可信原件字节读取；代码先交完整 commit 引用及报告。
- 一次小样本摩擦探针和一次配对对照，先判断收益，再完成实现。

不建设审查发现数据库、严格身份认证、任意接收边、候选生产排除清单、额度驱动、依赖准入或配送生命周期。普通审查发现通过冻结报告和回环传递，正常修复不增加逐项人工处置。Work `succeeded` 仍只表示流程完成，不能宣传为内容正确或全部验收通过。

## 成功判据

进入产品代码阶段前，3 个真实任务的摩擦探针完成；有一个受控返工场景和一个重开续接场景，记录人为注入与自然事件的区别。若额外配置和核对成本超过收益，停止或收窄，不按计划惯性实现。

最终在等价模型、宿主、标准和工作区条件下完成 5–8 个任务的配对对照，分别报告首次与复用人工分钟、质量、未完成、解释与重做量、墙钟和可取得的真实 usage。外部审阅判定任务是否可接受，不以 Work 状态充当真值。实验支持所测样本内的取舍，不宣称普遍收益。

所有机器事实来自实际工具、文件观察和 Store；报告列出的候选是实际被检查的完整 commit，不能从 agent 摘要或当前 HEAD 推断。终点结果与有效检查引用一致；缺失、非零、超时、部分执行、未知和普通审查均如实报告。相关正反例和真实宿主闭环通过，并由未参与实现的强模型审查。
