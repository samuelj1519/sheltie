# C008 候选设计

状态：`proposed`，实现 `not_run`。基准：`186ebd75d744fc2db83a72b715d36d05dd923883`。本文件是候选机制，不是当前架构；内容自 C006 design.md §4 拆出，并按独立审阅修订。

## 1. 分层

| 层 | 知道什么 | 不知道什么 |
| --- | --- | --- |
| sheltie-core | 依赖检查的三种状态与层；准入规则与运行时可用性政策；失效键与有效期的结构比对（纯函数） | skill 是什么、放在哪；宿主的搜索路径 |
| sheltie-runtime | 存取准入结果与使用记录 | 宿主的搜索路径 |
| 外围：依赖检查器 | 某个宿主某个版本的搜索路径和优先级；怎样判断遮蔽；怎样生成失效键 | Work 怎样推进 |

GF-01 不变：内核里不出现 skill 目录、宿主名或 Git 词汇。

## 2. 依赖检查器

```text
Workbook 声明（kind、name、来源、版本或摘要、必需/可选、运行时可用性政策）
   └── 外围检查器（按宿主与版本）：逐层检查存在、可解析、可用（可预检）
          └── CLI 写入准入结果（检查器与版本、宿主与版本、执行工作区、逐项逐层状态、失效键、有效期、证据指针）
                 └── attempt begin：DR-05 准入规则 + DR-06 结构比对通过，才允许开始
```

- 「可解析」要列出同名候选以及宿主会选中哪一份；判断不了宿主的选择顺序时记为未知；
- 「可用（可预检）」只包含能直接检查的项（引用的文件是否存在），给出满足、不满足或未知；需要运行才能知道的项不放进准入，按 Workbook 声明的 `stop` / `attempt-once` 处理；
- `attempt-once` 放行时，准入结果记下「已放行一次」；同一准入结果再次用于 `attempt begin` 时拒绝，要求重新检查；
- 失效键由检查器生成；引擎只比较它自己持有的那部分，并检查有效期。检查器可以把宿主版本、skill 摘要等引擎看不到的键写进结果，供重新检查时比对，但引擎不据此声称发现了变化；
- 使用记录分声明与观测。观测需要宿主通道；宿主没有提供通道时，只有声明。

检查器先以外部脚本形式参与探针实验，证据标为「外部回填」。

## 3. 准入拒绝的去向

| 条件 | 未采用 C005 | 采用 C005 |
| --- | --- | --- |
| 必需依赖某层不满足或未知 | `attempt begin` 拒绝；Work 状态不变；`next` 仍给 `attempt begin` 并附未满足项 | 另可进入可恢复等待或换合格备选 |
| 准入结果过期或失效键不符 | 同上，提示重新检查 | 同上；换执行者或宿主必然使旧结果失效 |
| `attempt-once` 已放行过一次 | 同上，提示重新检查 | 同上 |

不把准入拒绝写成 Attempt 失败，也不把 Work 置为 `blocked`：现行 GF-14 下非门槛 `blocked` 只能取消，这会把可修复的环境问题变成放弃任务。
