## 1. 机制 oracle

| 规则 | 合法例 | 反例 / 无法确认 | 预期 |
| --- | --- | --- | --- |
| 只读明确声明 | manifest 与 Node 明确引用真实资源 | 自然语言提到工具但无 requires | 只检查声明；后者不进入样本 |
| 存在与选择分开 | 已核固定版本规则选中声明对象 | 同名候选存在但解析顺序不明 | 存在可确认，选择 unknown |
| 缺失 | 完整宿主搜索闭包均获准且可观察 | 只在获准范围未找到，但还有未获准或未知搜索位置 | 前者确知无对象才 mismatch；后者存在/选择 unknown，保留范围内未发现证据 |
| 来源身份 | 可观察来源等于声明 | 同名对象来源不同或不可核 | 不同 mismatch，不可核 unknown |
| 版本语义 | 合同与观察有明确匹配规则 | 只知道范围文本，没有解释依据 | unknown，不按文本相等猜 |
| 摘要闭包 | 约定完整闭包的独立摘要一致 | 脚本资源未纳入摘要 | 未定义闭包 unknown；明确不符 mismatch |
| source 数据 | 原样记录声明 | source 含可执行或下载内容 | 不执行，不联网安装 |
| 输出无写入 | stdout JSON，临时 fixture 前后核对 | probe调用区间内Store/宿主/工作区字节或目录发生新增变化 | 机制失败，停止 |
| 运行时未知 | 预检结果准确保留 unknown | 网络/权限只能运行才知 | 人/协调者处理；不建内核准入 |
| 前后变化 | 第二次检查另生成观察 | 第一次以后宿主改动 | 不改第一次，不声称持续有效 |
| 使用来源 | 宿主原生可读记录 observed | 只有执行者声称 used | 单列 reported，不能回改预检 |

no-write 快照仅围绕 probe 调用；实际任务按现行引擎正常推进的 Store 写入单列，不作为探针违规。

合成缺失/遮蔽/摘要变化只发生临时 fixtures。禁止在用户宿主目录人为删除真实资源；机制结果不能进入真实失败/收益计数。

## 2. 真实价值实验

先固定任务、Workbook 与 Node 摘要、完整 requires、作者确认的必需性、宿主版本、解析规则依据、工作区、观察路径、脚本 hash、Python 版本和任务标准。人工核对与脚本核对读同一声明，记录顺序与熟悉度；样本不足只报告个案。

| 指标 | 口径 |
| --- | --- |
| 自然需求 | 实际任务是否因缺少该资源不能完成；人工确认与显式声明分别保留 |
| 预检成本 | 脚本准备、运行、解释 unknown 和复核所用时间 |
| 人工成本 | 按任务书声明直接核对所用时间；注明前次观察带来的熟悉度 |
| 明确发现 | 可复核的缺失/身份不符条目数；不把 unknown 算准确识别 |
| 执行中失败 | 原执行记录中可证实来自依赖的失败数；原因未知单列 |
| 错误提醒 | 资源可用却报告不符的条目与处理时间；不把未执行的任务当作误拦 |
| 未知比例 | 按检查项计数，分别列存在/选择/身份/运行时前提 |
| 净收益 | 人工成本减少与避免的实际损失，减去探针维护及复核成本 |

明确缺失时不强行运行任务制造失败；这种样本只报告提前发现，避免失败次数为无法精确估算。没有实际 requires/真实必需资源时，真实实验保持 not_run，结论是暂不需要产品化。

是否继续以真实净收益与重复需求为依据，不预设百分比门槛来筛选单次结果。夹具 PASS、查到很多已安装 skill、一次成功调用，都不证明应进入内核。
