# C008 验证

Candidate: `none`

状态：proposal 阶段。全部实验为 `not_run`。本文件先固定实验口径，避免事后调整指标。内容自 C006 validation.md 拆出，并按独立审阅修订。

## 1. 要回答的问题

1. **机制是否正确：** 缺失、遮蔽、版本不符、未知能否在开始前被识别，且不误拦。
2. **用户价值：** 因依赖问题而中途失败的执行是否减少。

机制正确不等于有用户价值（GF-19），分开报告。

## 2. 探针

- 先选一个宿主和一份真的带必需 skill 的 Workbook；核对该宿主固定版本的搜索顺序与遮蔽规则；
- 在任务样本中人为制造依赖问题：必需 skill 缺失、同名 skill 遮蔽、版本或摘要不符、检查器无法判断、运行时才知的外部工具缺失；
- 检查器先用外部脚本实现，只支持一个宿主；
- 对照：没有准入检查，按现状执行。

| 指标 | 口径 |
| --- | --- |
| 开始前识别率 | 依赖问题在开始前被识别的比例 |
| 中途失败 | 因依赖问题在执行中途失败的次数 |
| 误拦 | 依赖实际可用，却被准入检查拦下的次数 |
| 未知比例 | 检查结果为「未知」的比例；过高说明检查器价值有限 |
| 必需依赖出现率 | 样本 Workbook 中实际存在必需宿主资源的比例；过低则架构成本可能高于收益 |

## 3. 失败路径测试（与用户价值分开报告）

采用并实现后执行。以下场景都可以直接用程序测试，不需要调用模型。

| 场景 | 应观察到 | 不能出现 |
| --- | --- | --- |
| 三层预检全部满足，「已使用」未知 | 允许开始 | 因「已使用」未知被拦下 |
| 只有「可解析」不满足（同名 skill 来源不同，宿主会选中另一份），其余相同 | Attempt 不开始 | 当作满足 |
| 必需 skill 缺失 | Attempt 不开始，不消耗业务重试，Work 状态不变 | 开始执行后失败；Work 进入只能取消的 `blocked` |
| 检查器判断不了宿主的选择顺序 | 记为未知，必需依赖不开始 | 当作满足 |
| 运行时可用性政策为 `stop`，该项无法预检 | 不开始 | 开始 |
| 运行时可用性政策为 `attempt-once` | 放行一次，准入记录仍为未知；同一准入结果第二次拒绝 | 记为满足；无限次放行 |
| 可选 skill 缺失 | 开始，任务书写明警告 | 被拦下 |
| 准入结果过期 | 拒绝，要求重新检查 | 沿用旧结果 |
| Workbook 冻结的依赖摘要与准入结果的失效键不符 | 拒绝 | 沿用旧结果 |
| 换执行者后（采用 C005 时） | 旧准入结果失效，重新检查 | 沿用旧结果 |
| 准入通过，执行时未使用 | 使用记录如实为空或为声明 | 回溯改写准入结果 |
