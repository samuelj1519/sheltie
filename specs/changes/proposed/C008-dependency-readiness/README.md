## 范围约束

Attempt 开始前能否识别必需依赖（首批是 skill）缺失、被遮蔽或版本不对，避免执行到一半才暴露。

本 package 于 2026-09-27 从 C006 拆出：C006 原为「成果交付与依赖就绪」两个单元，[独立审阅](../C006-result-delivery/independent-review-2026-09-27.md)第 2 条指出一个目录无法分别表示两个单元的生命周期。需求来源与方向讨论见 [C006 review.md](../C006-result-delivery/review.md)；审阅第 1 条（准入与四层检查的矛盾）的修订落在本 package，答复见 [C006 review-response-2026-09-27.md](../C006-result-delivery/review-response-2026-09-27.md)。

## 要解决的问题

1. GF-28 只让 Workbook 按 `kind + name` 声明宿主资源，引擎把声明列进任务书，不检查宿主。skill 缺失或版本不对时，要等 agent 执行到一半才暴露。
2. `kind + name` 不足以确定身份：同名 skill 可能来自项目目录、用户目录或插件，内容不同；宿主按自己的搜索顺序选中其中一份。
3. 只给出警告不够：必需依赖不满足时仍然开始执行，失败会被记成执行失败，还要消耗业务重试。

## 首批用户

个人开发者的本地 Git 仓库；首批只支持一个宿主。

## 成功判据

采用前（proposal 阶段）：

- [validation.md](validation.md) 的探针已执行，按预先写定的口径报告，其中误拦与未知比例单独报告；
- 机制正确性与用户价值分开报告（GF-19）。

采用后：

- 依赖身份包含来源和版本或摘要；
- 准入只看执行前可检查的三层（存在、可解析、可用中的可预检部分），每层记录「满足 / 不满足 / 未知」；「已使用」只作事后记录；
- 运行时才能知道的可用性由 Workbook 声明政策，未知不被当作满足；
- 必需依赖准入未满足时 Attempt 不开始、不消耗业务重试；可选依赖只警告；
- 引擎只做结构比对，不自己观察宿主；准入结果过期或失效键不符时拒绝使用。

## 不做什么

- 不安装任何东西（GF-20 的安装工具仍后置），不写宿主配置（INV-3）；
- 不判断 skill 内容好坏，只判断身份与可用性；
- 不承诺准入通过的依赖在执行时一定被使用；
- 不承诺发现检查之后、未经重新检查的宿主侧变化。
