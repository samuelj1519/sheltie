# C008：单宿主外部依赖预检实验

状态：`proposed`
目标版本：`无产品版本；先做仓库内实验`
兼容性：`不改 Workbook、CLI 或 Store 格式`
基线：`17a1647758ceea5ebf637610ab2cdf91589c5218`
Owner：`待采用时指定`
权威性：候选实验；尚未采用，不实施探针，不进入内核。

本方案只回答一个问题：在实际需要宿主资源的任务中，执行前展示明确缺失或身份不符，是否比当前的资源声明和人工核对更省事。实验只支持一个实际宿主，不建立准入、有效期、执行绑定或安装系统。

## 产品目标与范围

Sheltie 把 `requires` 声明列入任务书，协调者已经可以据此检查资源。本实验比较人工核对与小型外部脚本的实际收益。脚本只读明确声明与宿主可观察资料，输出「符合 / 不符合 / 未知」及证据；未知由用户或协调者决定，不改变 Work、Attempt 或业务重试。

Workbook 的 `resource.*` 文件是随版本冻结的参考材料，不是宿主资源。没有实际必需宿主资源的任务不进入实验；不从自然语言 skill 说明、用户目录或安装数量推导必需依赖。

## 采用条件

- 有一份真实任务 Workbook 在 manifest 与 Node 中明确声明 `requires`，作者确认完成任务确实依赖其中至少一个资源。
- 已确定一个当前可用宿主及其版本，并能按官方说明或实际观察核对搜索与解析行为。
- 人授权只读实验。实验不会安装资源、改宿主配置、启动付费接口或执行资源声明的 source URL。

找不到满足条件的任务时，不采用本实验，记录「无真实必需资源，暂不需要产品化」。不通过人为增加 requires、扩大任务种类或安装资源制造需求。

## 成功判据

机制与价值分别判断：

- 能准确展示明确缺失、可观测的来源/摘要不符；无法可靠确认的项保持未知。
- 不把「存在」当作「可解析」，不把「可解析」当作「运行时一定可用或已使用」。
- 外部预检不修改 Store、宿主配置和工作区，不消费业务重试；预检之后的变化由再次检查发现，不承诺持续监控。
- 真实任务记录预检时间、人工核对时间、避免的执行中失败、错误提醒和未知比例。只有观察到重复需求和净收益才讨论产品化；一次夹具成功不满足该条件。

## 后续决定

实验结果可以是继续外部工具、仅完善任务书说明、或停止该方向。核心准入、执行绑定、结果缓存、TTL、宿主适配平台和安装能力都在[路线图](../../../roadmap.md)按真实需求决定，不在本 package 预写接口。
