## 1. 候选能力

编号 `DR-nn` 只在本 package 内使用；采用时再并入根规格的 GF 编号。

`DR-01` **依赖身份。** `kind + name` 之外，还包括来源或命名空间，以及版本或内容摘要。同名同类、来源不同的两个 skill 不是同一个依赖。这修改了 GF-28 中「同名同类声明在任何 Workbook 与宿主里都指同一资源」的假设。

`DR-02` **四层检查，前三层用于准入。**

| 层 | 问题 | 什么时候能知道 | 是否参与准入 |
| --- | --- | --- | --- |
| 存在 | 宿主的搜索路径里有没有这个依赖 | 准入检查 | 是 |
| 可解析 | 宿主实际会选中的是不是这一份（有没有同名遮蔽） | 准入检查 | 是 |
| 可用（可预检） | 能在执行前直接检查的前提：引用的文件、声明的目录是否存在 | 准入检查 | 是 |
| 可用（运行时才知） | 外部工具、网络、权限在执行时是否可用 | 只能执行时得知 | 否；按 DR-05 的政策处理 |
| 已使用 | 本次执行是否确实加载并使用了它 | 只能从执行后的使用记录得知 | 否；只作事后记录 |

`DR-03` **三种状态。** 每个检查对象的每一层，状态只取「满足 / 不满足 / 未知」。未知不等于满足，也不等于不满足；检查器没有办法判断的，一律记为未知。任何政策都不把未知改写成满足。

`DR-04` **准入检查与使用记录分开。** 准入检查在 Attempt 开始前由外围检查器完成，记录检查器及其版本、宿主及其版本、执行工作区、每个依赖每一层的状态、失效键与有效期（DR-06）。使用记录在执行后写入，分声明（执行者说用了）和观测（宿主通道显示用了）。准入检查通过不代表执行时一定用上；执行时用上了也不回溯改写准入结果。

`DR-05` **必需与可选，以及准入规则。** Workbook 声明依赖是必需还是可选；对含「运行时才知」可用性的必需依赖，还要声明运行时可用性政策。

- 必需依赖：存在、可解析、可用（可预检）三层都为「满足」，才允许开始。任一层为「不满足」或「未知」：Attempt 不开始，不消耗业务重试。「已使用」在开始前必然未知，不参与这条规则。
- 必需依赖的运行时可用性政策，闭集二选一：
  - `stop`：运行时可用性无法预先确认就不开始；
  - `attempt-once`：允许一次受限尝试。准入记录里这一项保持「未知」，任务书写明；每条准入结果最多放行一次 Attempt，这次 Attempt 失败后，要重新检查才能再次放行。失败按现行规则计入执行事实，Workbook 作者选择此政策即接受这一点。
- 可选依赖不满足或未知：可以开始，任务书里写明警告。
- 准入未满足时的去向：
  - 未采用 C005：`attempt begin` 以准入错误拒绝，Work 保持原状态（不进入只能取消的 `blocked`，GF-14），`next` 仍给出 `attempt begin`，并附上未满足的依赖与层，提示重新检查或交给人；
  - 采用 C005：还可以进入可恢复等待，或在 C005 冻结的执行绑定内换合格备选。

`DR-06` **准入结果的失效，只做结构比对。** 引擎自己观察不到宿主变化。外围检查器在准入结果里上报失效键（宿主标识与版本、执行工作区身份、每个依赖实际解析到的来源与摘要）和有效期。`attempt begin` 时引擎只做结构比对：有效期是否已过；失效键中引擎自己持有的部分（Workbook 冻结的依赖声明、采用 C005 时的执行者与宿主绑定、Work 记录的执行工作区身份）是否与当前一致。任一不符就拒绝并要求重新检查。宿主升级、用户改动 skill 文件等引擎看不到的变化，只有在检查器重新运行时才会被发现；这不在保证范围内。

`DR-07` **单宿主最小版本先行。** 首批只支持一个宿主。Claude Code 读取 `.claude/skills` 与 `~/.claude/skills`；Codex 读取 `.agents/skills`（从当前目录到仓库根逐级）、`$HOME/.agents/skills`、`/etc/codex/skills` 与旧路径 `~/.codex/skills`。搜索路径和优先级写在外围检查器里，按宿主版本记录，不进入内核；采用前按固定宿主版本复核。

`DR-08` **引擎不自己检查宿主。** 检查由外围检查器完成；引擎只保存闭集结果，并在 `attempt begin` 按 DR-05、DR-06 做结构检查。引擎不安装、不写宿主配置（INV-3）。

## 2. 承诺合同

| 承诺 | 信任前提与机制 | 强度 | 建议 |
| --- | --- | --- | --- |
| 必需依赖准入未满足时不开始 | 外围检查器的准入结果 + `attempt begin` 结构检查（DR-05、DR-08） | 正常接口会拒绝 | 实现；准入结果本身由检查器上报，引擎不核实其真实性 |
| 不使用过期或失效键不符的准入结果 | 有效期 + 引擎持有部分的失效键比对（DR-06） | 正常接口会拒绝 | 实现 |
| 检查之后宿主侧的变化会被发现 | 引擎观察不到宿主 | 不承诺 | 由检查器重新运行发现 |
| 运行时才知的可用性在开始前已确认 | 只能执行时得知 | 不承诺 | Workbook 声明 `stop` 或 `attempt-once` |
| 准入通过的依赖在执行时一定被使用 | 宿主行为；只能事后观测 | 不承诺 | 使用记录分开保存 |

## 3. 保证范围声明（对外用语候选）

可以说：

- 节点需要的必需 skill 在开始前会按存在、可解析、可预检的可用性检查；任何一项不满足或无法确认时，不会开始执行，也不消耗重试；
- 检查结果过期或与当前执行条件不符时，需要重新检查。

不能说：

- 检查通过的 skill 在执行时一定被使用；
- Sheltie 会发现你在检查之后对宿主或 skill 做的改动；
- Sheltie 会自动安装缺失的 skill。
