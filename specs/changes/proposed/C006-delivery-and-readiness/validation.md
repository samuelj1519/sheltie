# C006 验证

Candidate: `none`

状态：proposal 阶段。全部实验为 `not_run`。本文件先固定实验口径，避免事后调整指标。两个单元分开实验、分开报告。

## 1. 要回答的问题

1. **单元一的机制是否正确：** 交付请求、回执、恢复与终态例外是否按承诺工作。
2. **单元一的用户价值：** 用户是否不再需要自己寻找、复制和核对成果。
3. **单元二的机制是否正确：** 缺失、遮蔽、版本不符、未知能否在开始前被识别，且不误拦。
4. **单元二的用户价值：** 因依赖问题而中途失败的执行是否减少。

机制正确不等于有用户价值（GF-19），分开报告。

## 2. 单元一探针

- 复用 C004 阶段 1 的任务样本；导出组件先用外部脚本实现 design.md §3 的协议，送达记录标为“外部回填”，不改产品代码；
- 三种目标位置各至少一次：默认位置、项目目录内、自定义目录；
- 对照：同一任务，用户按现状从管理根找到并复制成果。

| 指标 | 口径 |
| --- | --- |
| 找到成果的时间 | 从 Work 结束到用户打开需要的文件 |
| 复制与核对的人工分钟 | 用户为确认“拿到的就是被接收的那一版”花的时间 |
| 送达错误 | 送错版本、漏送、覆盖了用户文件的次数 |

## 3. 单元二探针

- 在任务样本中人为制造依赖问题：必需 skill 缺失、同名 skill 遮蔽、版本或摘要不符、检查器无法判断；
- 检查器先用外部脚本实现，只支持一个宿主；
- 对照：没有准入检查，按现状执行。

| 指标 | 口径 |
| --- | --- |
| 开始前识别率 | 依赖问题在开始前被识别的比例 |
| 中途失败 | 因依赖问题在执行中途失败的次数 |
| 误拦 | 依赖实际可用，却被准入检查拦下的次数 |
| 未知比例 | 检查结果为“未知”的比例；过高说明检查器价值有限 |

## 4. 失败路径测试（与用户价值分开报告）

采用并实现后执行。以下场景都可以直接用程序测试，不需要调用模型。

**单元一：**

| 场景 | 应观察到 | 不能出现 |
| --- | --- | --- |
| 文件已写入，回执前进程退出 | 恢复时核对一致，补记回执 | 重新覆盖写入 |
| 部分文件写入后中断 | 只补写缺失部分 | 已写部分被重写 |
| 目标文件已被用户修改 | 送达冲突，交给人 | 覆盖用户修改 |
| 目标路径含越界符号链接 | 拒绝写入，送达失败 | 写到目标根之外 |
| 导出清单含 `..` 或绝对路径 | 拒绝 | 越界写入 |
| 目标根里有清单之外的文件 | 保持不动 | 被删除或覆盖 |
| 覆盖策略为 `refuse`，目标已有同名文件 | 送达冲突 | 静默覆盖 |
| 终态 Work 追加送达记录 | 成功，执行结果与接收结论不变 | 被拒绝，或改写了接收事实 |
| 终态 Work 上的其他写操作 | 仍被拒绝 | 借送达例外写入 |
| 协调者自报已复制 | 记为自报 | 显示为已送达 |
| 交付副本被删除 | 记为目标副本缺失，可重新导出 | 历史送达记录被改写 |
| 目标根暂时不可访问 | 记为不可访问 | 当作已删除 |
| 管理根唯一原件缺失 | `STORE_CORRUPT` | 用交付副本充当原件 |
| 修改结果根 | 形成新绑定版本，旧记录按旧绑定解析 | 旧记录指向新位置 |

**单元二：**

| 场景 | 应观察到 | 不能出现 |
| --- | --- | --- |
| 必需 skill 缺失 | Attempt 不开始，不消耗业务重试 | 开始执行后失败 |
| 同名 skill 来源不同，宿主会选中另一份 | “可解析”不满足 | 当作满足 |
| 检查器判断不了宿主的选择顺序 | 记为未知，必需依赖不开始 | 当作满足 |
| 可选 skill 缺失 | 开始，任务书写明警告 | 被拦下 |
| 换执行者后 | 旧准入结果失效，重新检查 | 沿用旧结果 |
| 依赖摘要变化 | 旧准入结果失效 | 沿用旧结果 |
| 准入通过，执行时未使用 | 使用记录如实为空或为声明 | 回溯改写准入结果 |
