# C006 产品 delta

状态：`proposed`，实验与实现均 `not_run`。基准：`186ebd75d744fc2db83a72b715d36d05dd923883`。本文件是候选变化，不是当前产品合同；采用后再同步到根 `spec.md`、`architecture.md`、`roadmap.md` 与 `contracts/`。

## 1. 三个根

| 根 | 放什么 | 谁写 | 用户能否编辑 |
| --- | --- | --- | --- |
| 管理根（`~/.sheltie`） | 权威 Store、冻结的 Workbook 副本、输入、Attempt 的原始产物、原始证据 | runtime，经 `confine()` 限定在管理根内 | 不应编辑；改动会被摘要核对发现 |
| 执行工作区 | agent 编辑代码的地方：用户仓库，或由宿主、外围组件提供的环境 | 宿主、agent、外围组件；Sheltie 记录环境身份与对应关系（C004 design.md §3.4） | 可以 |
| 结果根 | 交付副本、证据摘要、来源清单，以及按需导出的交接材料 | 独立导出组件，按 Work 创建时的授权 | 可以；交付副本本来就给用户用 |

**原则：** 管理根保存事实，结果根提供副本。结果根里的文件变化、缺失或暂时不可访问，都不改写管理根里的历史事实。

## 2. 单元一：成果交付

编号 `DL-nn` 只在本 package 内使用；采用时再并入根规格的 GF 编号。

`DL-01` **交付位置在 Work 创建时授权。** 三选一：默认位置、项目目录内的位置、自定义位置；默认值在采用时确定。授权记录目标根、用途、覆盖策略和绑定版本。修改目标形成新的绑定版本，旧的送达记录仍按旧绑定解析。

`DL-02` **管理根与结果根分工。** 管理根保留原始记录、冻结产物和原始证据；结果根只接收三类东西：已接收产物的交付副本、面向用户整理的证据摘要、来源清单。交接材料（C005 EX-01）只在请求时导出。中间产物不导出。

`DL-03` **交付请求。** 达到交付条件后，引擎给出一个交付请求。交付条件：采用 C004 时为受控接收点放行；否则为 Workbook 终点的 Attempt 成功。请求关联：

- 已接收的产物版本及其摘要；
- 导出清单：每项源产物对应的目标相对路径；
- 目标根的绑定版本；
- 覆盖策略；
- 请求标识。

请求一经生成就不再修改；要改只能取消后重新请求。

`DL-04` **独立导出组件。** 导出组件在 runtime 之外，消费交付请求：核对请求与源文件摘要，只写目标根内、导出清单列出的路径，不删除目标根里的其他文件。目标路径中的符号链接、重名和越界相对路径，都由导出组件按合同处理（design.md §3）。协调者、驱动层或用户都可以在交付条件满足后调用它，不必等用户回到终端；skill 可以教宿主调用，但不保存送达状态，也不判断是否需要重试（GF-18）。

`DL-05` **送达回执。** 送达只由导出组件的回执证明：回执列出实际写入的文件及其摘要、请求标识和完成时间，写入方式标为“导出组件”。协调者说“已经复制好了”，只能记为自报，不能等同于经过核对的送达。

`DL-06` **可恢复交付。** 最常见的中断是：文件已经写到目标，进程在回写送达状态前退出。恢复时先检查目标：

| 目标状态 | 处理 |
| --- | --- |
| 来源清单存在，请求标识和所有摘要一致 | 补记回执 |
| 部分文件已写入且与请求一致，其余缺失 | 继续写入缺失部分 |
| 目标文件与请求不一致（用户已编辑，或有其他内容） | 记为送达冲突，停下来交给人 |

不能直接重跑覆盖，因为用户可能已经开始编辑目标文件。GF-15 的幂等要求是设计基础，但它不会让管理根的数据库和外部文件系统形成一个原子事务，所以导出需要自己的恢复协议。

`DL-07` **终态后只追加送达记录。** GF-14 规定终态 Work 不再接受写操作。本 package 提出一条显式例外：终态 Work 的执行结果和接收结论保持不变；交付过程可以追加与指定已接收产物绑定的交付请求、回执和送达观测。这些记录在同一个 Store 里单独保存，不另建数据库；除此之外，终态 Work 仍不接受任何写操作。

`DL-08` **送达状态与后来的缺失分开。**

送达状态：未请求、已请求未送达、已送达、送达冲突、送达失败。

送达之后的观测另行记录，不覆盖送达状态，也不覆盖接收事实：

| 观测 | 含义 | 处理 |
| --- | --- | --- |
| 目标副本缺失 | 管理根的原件完好，只是交付副本不见了 | 可以从管理根重新导出，形成新的交付请求 |
| 目标暂时不可访问 | 外置磁盘未挂载、网络目录断开等 | 记为不可访问，不当作已删除 |
| 管理根的唯一原件缺失 | 证据缺口 | 按现有规则报 `STORE_CORRUPT`；交付副本不能反过来充当原件 |
| 交付副本被修改 | 用户在用它 | 不算证据缺口；来源清单的摘要用来区分“送达时的原样”和“后来改过” |

`DL-09` **持久引用不用绝对路径。** 交付请求、回执和来源清单里的位置，都记为 Work 标识 + 根绑定（用途与版本）+ 相对路径。任务书仍可给出绝对路径，因为它服务的是当次执行。

`DL-10` **不替用户改 `.gitignore`。** 目标根在 Git 仓库内时，是否忽略由用户决定。被忽略的交付副本会被 `git clean -fdx` 删除，这按“目标副本缺失”处理；未被忽略的会出现在 `git status` 里，这也是用户的选择。

## 3. 单元二：依赖就绪

编号 `DR-nn` 只在本 package 内使用。

`DR-01` **依赖身份。** `kind + name` 之外，还包括来源或命名空间，以及版本或内容摘要。同名同类、来源不同的两个 skill 不是同一个依赖。这修改了 GF-28 中“同名同类声明在任何 Workbook 与宿主里都指同一资源”的假设。

`DR-02` **四层检查。**

| 层 | 问题 | 什么时候能知道 |
| --- | --- | --- |
| 存在 | 宿主的搜索路径里有没有这个依赖 | 准入检查 |
| 可解析 | 宿主实际会选中的是不是这一份（有没有同名遮蔽） | 准入检查 |
| 可用 | 它需要的工具、权限、文件是否具备 | 准入检查；部分只能标为未知 |
| 已使用 | 本次执行是否确实加载并使用了它 | 只能从执行后的使用记录得知 |

`DR-03` **三种状态。** 每个检查对象的每一层，状态只取“满足 / 不满足 / 未知”。未知不等于满足，也不等于不满足；检查器没有办法判断的，一律记为未知。

`DR-04` **准入检查与使用记录分开。** 准入检查在 Attempt 开始前由外围检查器完成，记录检查器及其版本、宿主及其版本、执行工作区、每个依赖每一层的状态。使用记录在执行后写入，分声明（执行者说用了）和观测（宿主通道显示用了）。准入检查通过不代表执行时一定用上；执行时用上了也不回溯改写准入结果。

`DR-05` **必需与可选。** Workbook 声明依赖是必需还是可选。

- 必需依赖任何一层为“不满足”或“未知”：Attempt 不开始，改为等待、在 C005 冻结的执行绑定内换合格备选，或交给人；不消耗业务重试；
- 可选依赖不满足或未知：可以开始，任务书里写明警告。

`DR-06` **重新检查。** 以下变化后，旧的准入结果失效，需要重新检查：换执行者或宿主（C005）、执行工作区变化、依赖版本或摘要变化、宿主版本变化。

`DR-07` **单宿主最小版本先行。** 首批只支持一个宿主。Claude Code 读取 `.claude/skills` 与 `~/.claude/skills`；Codex 读取 `.agents/skills`（从当前目录到仓库根逐级）、`$HOME/.agents/skills`、`/etc/codex/skills` 与旧路径 `~/.codex/skills`。搜索路径和优先级写在外围检查器里，按宿主版本记录，不进入内核。

`DR-08` **引擎不自己检查宿主。** 检查由外围检查器完成；引擎只保存闭集结果，并在 `attempt begin` 做结构检查：必需依赖都有有效的“满足”记录才允许开始。引擎不安装、不写宿主配置（INV-3）。

## 4. 承诺合同

| 承诺 | 信任前提与机制 | 强度 | 建议 |
| --- | --- | --- | --- |
| runtime 只写管理根 | `confine()` 限定管理根；结果根由导出组件写 | 正常接口会拒绝 | 实现 |
| 导出组件不写授权范围之外的位置 | 只写目标根内、导出清单列出的路径；不跟随越界符号链接 | 正常接口会拒绝 | 实现；同权限程序仍可改写用户文件 |
| “已送达”有工具回执 | 回执由导出组件产生（DL-05）；自报另记 | 正常接口会拒绝 | 实现 |
| 中断后不盲目覆盖用户已编辑的文件 | 恢复先核对来源清单与摘要（DL-06） | 正常接口会拒绝 | 实现 |
| 后来的缺失不改写历史事实 | 送达观测只追加（DL-07、DL-08） | 正常接口会拒绝 | 实现 |
| 送达后的副本保持原样 | 用户可以编辑 | 不承诺 | 来源清单用来识别改动 |
| 必需依赖不满足时不开始 | 外围检查器的准入结果 + `attempt begin` 结构检查（DR-05、DR-08） | 正常接口会拒绝 | 实现 |
| 准入通过的依赖在执行时一定被使用 | 宿主行为；只能事后观测 | 不承诺 | 使用记录分开保存 |

## 5. 保证范围声明（对外用语候选）

可以说：

- 成果会送到你在创建任务时授权的位置；送达有工具回执，中断后可以恢复，不会盲目覆盖你已经改过的文件；
- 交付副本丢了，可以从管理根重新导出；它的变化不影响历史接收记录；
- 节点需要的必需 skill 在开始前会被检查；不满足或无法确认时，不会开始执行。

不能说：

- 送达后的文件一定保持原样；
- 检查通过的 skill 在执行时一定被使用；
- Sheltie 会自动安装缺失的 skill；
- 导出组件阻止了其他程序改写目标目录。
