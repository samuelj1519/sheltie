# C007 规格：先验证固定模板

状态：`proposed`；所有实验 `not_run`。本文只定义实验的输入、过程和判断，不增加引擎行为。

## 1. 假设与比较

假设：多数首批任务需要不同任务内容，而不需要不同工作图。已有 `workbooks/spec-dev`、`examples/` 提供可读的方法参考；固定图、独立审查与明确返工上限可能已经足够。

| 组别 | 可以使用 | 不得使用 |
| --- | --- | --- |
| A：直接编写 | 相同任务目标、标准、现行合同、现有 examples 与同型号 agent 辅助；可自行设计当前格式 Workbook | B 组新增的审定固定模板和其填写提示 |
| B：模板填写 | 相同目标/标准/合同/型号 agent；固定模板、填入任务说明与验收输入 | 修改图、门槛、次数上限、必需检查、标准来源或最终结果选择 |

两组的生成者都使用同型号简单模型，使用独立新会话；强模型仅在实验开始前搭模板与 oracle，正式盲审由未参与模板/样本编写的强模型执行。两组按任务配对、交错执行；同一人先做另一组带来的熟悉效应通过预注册顺序和记录披露。无法控制的差异单独列出，不把相关性写成因果结论。

首次接触项目的实验执行者只需具备 Rust/CLI 基础，先做一个不计时的现有例子练习，正式任务时按冻结步骤执行。

## 2. 生成输入与可修改边界

目标、交付对象、必须检查、人工门槛、失败返工与次数上限由任务提供者和模板作者先定。简单模型可以报告缺项和提出建议，但建议不自动成为新标准。

模板包包含：固定 `workbook.toml`/Flow/关键说明，允许填写的任务文本位置，起始输入键说明，一份第一次使用者操作说明。业务参考文件尽量通过现有 `resource.*` 随版本冻结，外部任务内容通过 `start.*` 输入；不为普通文件需求新增 `requires`。

B 组只能修改白名单里的任务文本和任务输入。若任务不能表达为现有模板，输出「模板不适配」及具体缺口，停止该样本；不得自己加节点/边或压缩必需审查。只在真实不适配样本达到预注册条件后，提出自由生成图的独立后续提案，本实验不实现检查器。

## 3. 校验与确认

| ID | 要求 |
| --- | --- |
| WG-01 | 生成物是普通当前格式 Workbook；没有实验专属协议、临时启动入口或 `plan.lock`。 |
| WG-02 | 草稿先复制为一个不再由生成者编辑的私有输入副本，再在专用临时 `SHELTIE_HOME` 执行现有 `workbook add/show/verify`。所有命令显式 `--home`，禁用对正式管理根的隐式回落。 |
| WG-03 | 校验摘要、图、说明、标准、盲审和安装确认都指向同一个私有副本。原始草稿随后改变不能影响这条检查链。 |
| WG-04 | 结构合法仅证明现有装入规则通过，不证明说明合理、标准充分或约束在真实运行中满足；这些由盲审和已有运行机制分别回答。 |
| WG-05 | 用户明确确认该副本摘要与内容后，才可从同一副本执行正式 `workbook add`；返回摘要必须与临时装入摘要相同。不同则停止，不开始 Work。 |
| WG-06 | 简单模型不改固定 oracle、盲审规则或原始失败记录；失败样本不悄悄重做成成功。修改后作为另一版样本记录，原记录保留。 |
| WG-07 | 实验不会自动安装 skill、subagent 或 MCP；需要宿主机制时仅记录现有 `requires` 声明，不能声称已就绪。 |

私有副本是为控制实验输入，并非同 OS 账户上的安全授权边界。摘要相同只证明字节相同，不证明授权来自真人。实验记录明确用户确认方式与内容；不从可改文件推导独立真人认证。

## 4. 完成后的产品判断

达到 [README 成功判据](README.md#成功判据) 时，先保留模板+填写说明这种最小能力，提出是否分发模板的候选。未达标时区分模板覆盖不足、说明生成错误、操作成本和样本局限；缩小或停止，不把失败解释成必须开发更复杂的 checker。

自由生成图仅在至少两项真实样本因固定图无法表达而失败，且这些任务确属首批目标时，才值得单独评估。单个特殊任务、生成者不懂语法、缺好说明或当前模板遗漏节点，都不直接证明需要一个新平台。
