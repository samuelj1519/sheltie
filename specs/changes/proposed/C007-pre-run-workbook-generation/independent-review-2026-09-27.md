# C007 独立方案审阅（2026-09-27）

审阅对象：本 package 的五份提案文档；对照当前 Workbook/Flow 合同、GF-03/GF-17/GF-26 与 C004/C005 的候选边界。本文件不改变 `proposed` 状态。authoring 实验与检查器失败路径测试均为 `not_run`。外部依据见 [一手来源笔记](../../../research/2026-09-27-agent-rust-guidance.md)。

## 结论与产品价值

**先做运行前生成实验是四份提案中成本最低、可独立推进的一步；当前保证用语和检查器入口需要修订。** 让 agent 起草普通 Workbook、由独立检查器核对机械约束、用户确认后按现有安装路径运行，符合「人负责方法、引擎只做机械判断」。方案清楚地区分运行前生成与 GF-26 运行中展开；用图可达性检查绕过路径，比只看「节点存在」有用。若一次性任务的编写时间明显下降且结果质量保持，才有产品化理由。

OpenAI 与 Anthropic 的近期建议支持保持简洁的 agent 工具链、在文件里保留可检查的约束并用独立评价反馈；它们没有证明生成的 Workflow 自然正确。生成流程还有用户整理约束、审阅映射与处理检查结果的成本，必须计入总人工时间。首阶段继续用现有 `workbook add`，可避免过早引入临时启动入口和第二套图状态。

## 采用前需修订

1. **高：第一阶段的保证强度与入口不一致。** `spec.md` §5 说「生成的流程必须满足你事先确认的检查、审查和门槛要求」「规划 agent 不能自己删掉」，但 `design.md` §4/§6 承认外部检查器可被跳过，普通 `workbook add` 不核对锁定文件；草稿中某个被映射节点是否真做审查也无法验证。第一阶段只能说「按指定检查器处理、且用户确认映射的草稿，在已检查的结构规则上通过」。第二阶段若要求正常接口拒绝绕过，必须有可信的签发来源和 `work start` 校验合同；单纯核对同权限可改的摘要只证明字节一致，不证明用户授权或标准充分。
2. **高：`WG-03` 的「可装入」检查必须无产品副作用。** 目前公开入口 `workbook add` 会复制并登记 Workbook；`design.md` §5 又把它放在检查之后正式安装。若检查器直接运行 `workbook add`，可能提前安装未确认的草稿，正式安装又撞同一版本。第一阶段用独立临时 `SHELTIE_HOME` 验证，或调用与安装共用的纯解析/编译入口；记录所检查草稿的摘要，用户确认与正式安装前再核同一字节。装入失败不能留下正式 Store 状态。
3. **高：静态检查的输入可信度是主要未决点。** 路径覆盖算法对给定图和映射是合理的，但候选生产节点集合 `P` 与约束映射均由规划者声明，再由用户确认；漏标一个产出新候选的节点、把「审查」映射到空壳节点，检查仍可能通过。WG-05 已承认内容无法判定。实验应有两类负例：可绕过的真实图路径，以及映射或 `P` 故意遗漏但图结构本身合规；后一类应报告为「需用户发现」或通过 C004 运行证据补强，不能计成检查器已拦截。
4. **中：未采用 C004/C005 时要收窄约束字段。** `README.md` 允许第一阶段直接实验，`WG-01` 又把 C004 验收合同和 C005 执行绑定写为约束来源；它们目前都只是 proposed。首阶段可用现有 Workbook 已表达的门槛、图、上限与 `requires`，其余候选字段只做实验记录，不称为运行时授权或接收机制。若实验目标包括「证据绑定被接收候选」，必须等 C004 相关接口采用和实现后另测。
5. **中：锁定文件必须绑定完整检查输入与结果。** `design.md` §4 的示例只有约束摘要、计划摘要、版本和 `result=pass`，还允许 `unresolved` 非空。采用时应区分「所有可检查规则通过，另有未决条目」与「整份约束均已满足」，保存用户实际确认的差异和映射摘要；任何计划或约束变更重算、重新确认。第二阶段若引擎核锁定文件，先定义谁可签发、如何记录用户确认、以及在单用户同权限下能承诺的强度。

## 推进建议与验收口径

先在 3–5 个真实任务上执行外部生成流程；手写组也允许 agent 协助写文件，才可测量「生成 + 检查 + 确认」的真实增量。记录首次与复用任务的人工分钟、结构缺陷、映射错误、最终审阅质量、未到达节点和 token/墙钟成本。检查器脚本先有纯图反例与确定的输入闭包，尤其是 `branch` 绕过、`back` 返工后未重新验证、空/错映射、预算无法结构判定和确认后文件改动。只有这一步显示净收益，才审定 ADR-E 或考虑 WG-09/WG-10。

**建议状态：保留 proposed；可先执行不改产品代码的实验，但不将实验锁定文件写成现行产品保证。**
