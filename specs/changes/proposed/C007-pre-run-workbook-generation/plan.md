# C007 实施计划

状态：`proposed`；所有任务 `todo`，所有实验 `not_run`。人采用后本表是唯一实施进度来源。先读 [共同实施指南](../../../guides/proposal-implementation.md)、[规格](spec.md)、[设计](design.md) 和 [验证](validation.md)。

## 1. 给首次接触项目的实现者

本方案不改 Rust 产品代码。现有 CLI 在 `crates/sheltie-cli/src/commands/workbook.rs::{add,show,verify}`；调用合同在 [公开协议](../../../contracts/protocol.md) 的同名段落；文件结构在 [Workbook 合同](../../../contracts/workbook.md)。模板参考 `workbooks/spec-dev/flows/default.toml` 和 `examples/` 中真实 Workbook，不从提案字段推断引擎能力。

共同工作流是强模型先搭固定图、说明边界、脚本与手写测试，再由简单模型填任务文本并照命令执行；每个里程碑由独立强模型审查。后续阶段只冻结当阶段确需的资产，不一次搭整个工具平台。简单模型不得修改 oracle、测试、固定图、阈值或此前原始运行记录，发现缺口就交回强模型。

实验文件都在采用后的本 package `experiments/`，运行临时 Home 位于专用临时目录。每条引擎调用显式 `--home`，真实正式 Home 不用于试装。没有 Rust 归属测试的任务不运行 `scripts/task.sh`；运行这里冻结的 Python 脚本测试、实际 CLI 样本与文档检查。提交要求按工程规范与共同指南执行；采用前不运行任务检查，不创建实验资产或登记 Workbook。

## 3. M1：第一次可用的模板体验

### C007-T01：搭模板、独立 oracle 与实际命令

**Owner / 依赖。** 强模型；人采用实验、指定当前真实引擎版本与独立审查者。无需等待 C004–C006/C008。

**读取与范围。** 读 `CONTEXT.md`、上游 Workbook/协议/工程合同；源码只读 `crates/sheltie-cli/src/commands/workbook.rs::{add,show,verify}` 和 `crates/sheltie-runtime/src/workbook_repo.rs::WorkbookRepo::{add,load,verify}`；读 `workbooks/spec-dev/flows/default.toml` 与 `examples/` 的真实文件。只在本 package `experiments/{templates,fixtures/pilot,oracle,prompts,scripts}` 新建资产与 README/protocol；不改产品 crate、workspace、全局 skill 或已有样例。

**输入 / 输出。** 输入：一个真实小代码变更目标、一个真实文稿目标、当前 CLI。输出：两份固定图和允许填写位置、任务输入、独立质量检查表、A/B 提示、首次读者步骤、可直接执行的同副本临时校验脚本和测试。

**步骤。** 1. 列两项目标的必需交付、检查、审查、门槛与返工，和人确认仍属首批需求。2. 从已有方法收窄出两份模板，固定图字节、次数上限和不可编辑说明。3. 把任务差异放进允许说明或 `start.*`，参考文件用 `resource.*`；不引入候选未实现字段。4. 完整实现 `validate-draft.py` 的私有复制、唯一 run 路径、临时 Home、真实 add/show/verify、stdout/stderr/退出码和摘要收集。5. 为脚本与边界写手工正反 fixture。6. 冻结两组提示、同模型参数、pilot 顺序和计时字段；把 T02 命令块替换为真实路径与参数。

**验收用例。** 合法草稿可装入临时 Home；非法边、缺 instruction、未知字段真实拒绝；改 B 组固定图被记录为失败；原稿复制后变更不影响私有副本；无确认不写正式 Home，哨兵/Store登记不变；源路径与 run 输出冲突不覆盖；清理仅限自建 temp。

**测试与归属。** 强模型完整编写 `experiments/scripts/test-validate-draft.py` 与 fixture，归 T01。脚本测试是调用方正确性检查，不能 fake 引擎通过；合法/非法装入和摘要比较必须用真实 binary。T02 只能执行测试，不改文件。不复刻 C002 digest算法与安装状态机。

**停止。** 模板需要新增引擎字段、脚本需要读取 Store、引擎不能显示所需事实、同副本链不成立时停止该范围并回到最小当前接口；不得先造 checker。

**命令 / 交接 / 提交。** 采用后在仓库根构建固定版本：`RUSTC_WRAPPER= cargo build -p sheltie-cli --message-format=json`（配隔离 `CARGO_TARGET_DIR`），从 Cargo JSON 的 `executable` 取绝对路径。运行 T01 冻结的 `python3 <package>/experiments/scripts/test-validate-draft.py --sheltie <absolute-binary>`、`scripts/check-docs.sh`、`scripts/check-specs.sh`；其他提交门禁沿工程规范。交接真实路径/参数、合法与非法原始输出、模板/fixture/test hash 与 T01 commit；一任务一提交。

### C007-T02：生成并使用首批两项草稿

**Owner / 依赖。** 简单模型初级执行者；T01 完整操作包。质量盲审交给未参与生成与模板的强模型。

**读取与范围。** 读 T01 的 `experiments/protocol.md`、各模板的 README、A/B 提示与两项 pilot 输入。仅创建 `experiments/runs/pilot/` 的原始草稿、私有副本、计时、命令输出与盲审；不改模板、测试、oracle 或目标标准。

**输入 / 输出。** 输入：两项相同目标与标准，每项 A/B 独立会话。输出：四份草稿及真实校验、人工活动时间、不适配/失败与独立质量意见，首次使用的操作痛点。

**步骤。** 1. 先按已有例子做一次不计时练习。2. 按冻结顺序运行同型号简单模型，A 直接编写、B 只填白名单文本。3. 运行 T01 校验脚本，固定同私有副本，保存实际 add/show/verify 和摘要。4. 按规定随机编号给独立强模型盲审，不展示组别/时间。5. 记录用户仍需要补什么、哪里不能执行、不适配的具体图需求；不自行修模板。正式安装不是此任务必要动作。

**验收用例。** 一项正常模板能以首次读者步骤完成；另一项缺输入/固定图不适配时准确停止，不越权改边；同样失败 A/B 都保留原始产物。草稿改变不改变已核副本。

**测试与归属。** 运行 T01 脚本测试与真实样本，测试/fixture不可改。无 Rust 归属测试，不调用 `task.sh`。T01 后卡中应有确定的校验脚本命令，而不是由初级自行猜 CLI flags。

**停止。** 模板边界未写明、必需标准缺失、需要新节点/门槛、正式 Home 参数隐式回落时停止样本并交 T01。一次失败不覆盖重跑；修后另建 run ID。

**命令 / 交接 / 提交。** T01 冻结的四次 `validate-draft.py` 命令、Python测试、文档检查与 `scripts/check-task.sh C007-T02 <T01提交> --staged`；工程门禁沿共同指南。交接四 run ID、活动/等待时间、私有副本摘要与失败；一任务一提交。

### C007-M1：独立强模型审查

从真实首次读者输出检查图是否最小、标准来源明确、普通返工不强制人介入、必要门槛保留、最终产物可找；重跑临时 Home 哨兵、同副本摘要与错误路径。核对 pilot 不适配是图局限、说明不足还是执行错误。结论通过才进入正式样本；需修改交回 T01，保持原失败证据。

## 4. M2：六项真实配对实验

### C007-T03：冻结正式输入、盲审与计时

**Owner / 依赖。** 强模型正式实验设计者；M1 通过候选。正式盲审者不得是本任务 oracle 作者。

**读取与范围。** 读 M1 findings、两份模板、pilot 原始失败及 [validation.md](validation.md)。可改 `experiments/templates/` 以修有依据的问题、`protocol.md`、`prompts/`；新建 `fixtures/formal/` 六项目标、`oracle/` 盲审标准、正式随机编号映射与计时表；需要脚本修正时连同调用方回归在本任务完成，单独说明真实失败。禁止改 pilot 原始 runs。

**输入 / 输出。** 输入：真实近期六项需求（至少两代码、两文稿）和 pilot 根因。输出：正式 input closure、固定顺序/模型/提示、独立质量 oracle、样本与错误定义、每一步的实际命令、T04 白名单。

**步骤。** 1. 在看到正式产物前固定完整六项目标，不为模板适配删标准。2. 预注册 A/B 交错顺序、相同模型/环境、独立会话和活动计时。3. 定义阻断/重大缺陷与适配失败。4. 固定成功门槛和缺数据处理；pilot 不进统计。5. 将 T04/T05 所需测试/脚本/算式换成真实名称，交接强模型盲审的完整指令与不许读取的组别映射。

**验收用例。** 同一手写样本 A/B 编号后得到同 oracle；缺必需检查、绕门槛、无限回环与产物不明都能识别；一项无法用图表达的任务能被记为不适配，不通过降标准修成成功。计时表能区分活动与等待，不接受缺失字段静默作零。

**测试与归属。** 正式 oracle 是强模型定义的人审标准，不包装成 Rust 单元测试。脚本变化由本任务补真实 caller 回归，T04不可改；若无脚本变化复用同输入闭包已有测试，不重复扩大全仓验证。

**停止。** 不够真实任务、无法取得可比模型、oracle 与任务标准冲突、盲审者不独立时先列缺口；不能以虚构任务补数。

**命令 / 交接 / 提交。** Python 脚本检查、真实一正一反 fixture、文档检查与 `scripts/check-task.sh C007-T03 <T01提交> --staged`；工程门禁沿共同指南。交接完整候选 hash、六输入摘要、协议/提示/模板/oracle摘要、顺序和命令；一任务一提交。

### C007-T04：按合同执行正式实验

**Owner / 依赖。** 简单模型初级执行者；T03 冻结协议。独立强模型负责正式盲审，不改生成物。

**读取与范围。** 读 T03 protocol 与提示，按组别只读取允许文件；只创建 `experiments/runs/formal/` 的十二份草稿、副本、时间、stdout/stderr/退出码、盲审与输入记录。不读盲审答案，不改模板、脚本或前面失败。

**输入 / 输出。** 输入：六项成对目标、同模型、冻结环境。输出：全部十二 run 的真实原始证据、失败/不适配、用户补标准次数与匿名盲审结果。

**步骤。** 1. 验输入摘要、模型/版本与顺序。2. 每组新会话照提示生成；B 只改白名单内容。3. 同副本校验，记录所有活动/等待。4. 给独立盲审者随机编号内容和固定标准。5. 完整保存失败，不重跑选好结果；协议外干预单独标注。

**验收用例。** 正常任务可装入且必需步骤保持；失败样本也有完整原始输出；模板不适配算入六项覆盖，模型调用失败和目标缺信息不被伪装成模板通过。脚本哨兵证明无未确认正式安装。

**测试与归属。** 只执行 T01/T03 固定测试与真实十二样本；不改测试与 fixture。无 Rust `task.sh`。盲审过程保留完整输入、模型与输出，不只存一个 PASS 字段。

**停止。** 模型、输入或模板摘要漂移则暂停后续样本，交回 T03判断是否新实验；源任务需要外部授权则停止相关动作，仍可完成 authoring 检查。

**命令 / 交接 / 提交。** T03 冻结的十二命令、Python测试、文档检查与 `scripts/check-task.sh C007-T04 <T03提交> --staged`；工程门禁沿共同指南。交接全部 run ID/摘要、失败与盲审，无结论先验；一任务一提交。

### C007-T05：从完整证据提出产品决定

**Owner / 依赖。** 强模型产品分析者；T04 全部原始记录。M2 仍由其他独立强模型执行。

**读取与范围。** 读预注册 protocol、六项目标、两组全量 runs、盲审和模板成本。只写 `experiments/report.md`、本 package `validation.md/progress.md`；不改阈值、原始时间、盲审、模板或生产代码。

**输入 / 输出。** 输入：配对活动时间/等待/token/费用、适配与缺陷事实、前置模板/盲审成本。输出：完整逐样本表、主要指标的可复算输入与算法、缺数据/样本局限、继续模板/缩小/停止建议。

**步骤。** 1. 检验样本闭包与所有失败是否保留。2. 分开计算活动时间中位数、墙钟等待与模型成本；基线为零或时间不可比时写不足，不制造百分比。3. 核适配至少五项、零阻断、重大缺陷不增加。4. 单列强模型前置成本和复用次数的敏感性，不声称确定盈亏。5. 分类未达标根因；只有真实固定图不足达到条件才提出独立自由图候选。6. 填最终验证表，安装未获确认就保留 `not_run`。

**验收用例。** 正负结果都能得出诚实建议；失败样本未被删、既有 C002 PASS 不替实验执行、authoring 可装入不被写成任务交付成功。手工小数组可复核中位数与百分比，缺失值不能作零。

**测试与归属。** 无新 Rust测试，采用表/小脚本计算时以手算期望核对；本任务不修改盲审 oracle。复用脚本检查列原 run ID和同闭包，不强行重复全套。

**停止。** 缺原始时间、未盲审、正式样本不足或生成者读过答案时据实际影响降结论/重设新实验，不补编数据。

**命令 / 交接 / 提交。** 固定计算命令或逐项手算输入、文档检查与 `scripts/check-task.sh C007-T05 <T03提交> --staged`；工程门禁沿共同指南。交接候选、完整证据表与产品建议；一任务一提交。

### C007-M2：独立强模型审查

独立重算活动时间与覆盖，抽查全部失败与盲审，检查组别同条件、顺序效应和生成者/标准作者/审查者分离。结论明确模板方向是否值得继续、证据只能覆盖哪些任务、哪些承诺仍 `not_run`。审查通过只结束实验，不自动安装正式 Workbook、分发 skill 或实施自由图 checker。
