# C007 实施计划

状态：`proposed`；任务均为 `todo`，实验与独立里程碑均为 `not_run`。人采用后本表是唯一进度来源。

每个任务和审查的范围基准都是本任务开工完整提交；提交前加 `--staged`，提交后用同一完整提交再核，不采用 README 总基线或随意 HEAD。准备/操作任务无 Rust 所属测试时不调用 task.sh。

## 1. 首次阅读与职责

初次参与只需先读 [README](README.md) 的目标与范围、[规格 §2–4](spec.md#2-配对与样本)、[设计 §3–4](design.md#3-当前-cli-的实际路径) 和 [验证 §3](validation.md#3-分析口径)，再读自己的任务卡。实际运行者的直接入口是 T01 制作的 `experiments/first-use.md`；该文件必须有完整步骤、真实参数位置、预期输出、退出码与停止方法，不能让初级开发者猜产品规则。

本方案不改 Rust 产品代码。只读源码入口与职责如下；需要理解一个命令时只读对应入口及 [公开协议](../../../contracts/protocol.md)，不先通读全仓。

| 入口 | 职责 |
| --- | --- |
| `crates/sheltie-cli/src/commands/workbook.rs::{add,show,verify}` | 装入校验、摘要视图与完整性核对；show 不是完整说明书 |
| `crates/sheltie-cli/src/commands/work.rs` 的 start 分支与 `status` | 创建 Work、返回冻结定义与查看当前合法操作 |
| `crates/sheltie-cli/src/commands/attempt.rs::{begin,submit,fail}` | 获取实际任务书/输出路径、封存产物、记录执行失败 |
| `crates/sheltie-cli/src/commands/gate.rs` | 仅真实授权边界下执行批准 |

复杂模型或有经验作者在 T01 完整准备方法、实验协议、oracle、必要脚本和测试。M1 由独立复杂模型先审可执行性与首次读者材料。T02 由简单模型或初级开发者按冻结手册运行与记录，真实任务使用者、助手、批准人与质量审阅者承担各自真实动作，不能由记录者编造。T03 由复杂模型分析根因，M2 由独立复杂模型审实际结果。

## 2. 阶段一：C007-T01 完整准备实验

**输入与允许范围。** 当前真实 binary、三项尚未解决的近期任务、现有本地检查、参与者和授权仓库副本。只制作本 package 的 experiments/，不改产品 crate、现有 examples、分发 Workbook 或宿主配置。方法参考 workbooks/spec-dev/，按 [设计 §2](design.md#2-固定代码方法) 收窄，不预建未来平台。

**步骤与预期交付。**

1. 核预算和授权，再固定 task 的目标/验收与 project 的上下文、初始仓库及检查。给两组独立副本。默认无 gate；真实不可替代授权例外及两组等价动作提前写入 protocol.md。
2. 完整制作 confirmed-input/ 和文字一致的 shared-method.md。真实 add/show/verify 必须可用；完整 Flow、说明、资源和上限由非执行者读同一副本审阅，不把 show 摘要代完整材料。
3. 固定三项配对顺序、模型/宿主/环境、actor × arm 初始真实历史和各组三次分配，记录跨组熟悉度、首次读者、所有助手、预算、自然/注入返工及停止。质量 oracle 和 [完整成本公式](validation.md#3-分析口径) 在结果前冻结。
4. 完整制作 first-use.md 和 run.json 示例。方法与公共准备成本、各组配置/维护、每次 run、纯实验开销各用唯一成本桶；未知 usage 为 null，默认无 gate 的交付及流程外接受/盲审步骤完整。
5. 只有记录确需自动化才制作 `experiments/scripts/collect_run.py` 及必要测试；安全 Home、唯一输出路径、原命令/退出码收集和错误处理由复杂模型完整实现，不留填空，不复刻 parser、摘要或 Store。
6. 用真实 CLI 跑一个合法装入和一个临时非法输入拒绝例，保存完整输出和副作用检查；必要脚本的安全边界用独立手工 oracle。没有新 Rust 用例，不人为制造红灯。

**first-use.md 必须交付的步骤表。** 每行给实际命令、参数文件位置、预期 stdout/退出码、产物位置与失败动作。

| 步骤 | 参数与预期 |
| --- | --- |
| 准备核对 | 固定 binary、Home、protocol commit、task/project、actor 历史和授权目录；任一不符停下 |
| A 组运行 | 固定原生提示/skill/脚本及保存位置；真实执行原件、候选与检查记录齐全，不调用 Sheltie |
| B 组运行 | 真实 add/show/verify、start、begin、submit/fail、status 命令；每次显式 --home，从响应读取真实 brief_path/outputs/next |
| 关闭重开 | 指定阶段、旧执行者停止证据、新会话自然材料和恢复步骤；不创建替换 Attempt |
| 交付与审阅 | 保存 patch/候选/检查；默认无 gate，真实授权例外才批准；用户接受与独立盲审流程外分别记时 |
| 记录与退出 | 唯一 run 目录、raw stdout/stderr/exit、活动及 usage；缺字段或非预期退出停止，不覆盖原件 |

CLI 成功退出 0 且 ok=true；业务拒绝退出 1、参数解析错误退出 2，均保留 JSON/stderr 事实并按手册停止。任务自身检查非零记真实失败，不改标准重跑。装入成功、目录存在或脚本退出零都不能代替最终质量。

**验收与停止。** 完整手册可以由首次接触项目、具备 CLI 基础的人执行；两组 task/project、方法文字与质量相同，原生配置认真且成本可见；合法/拒绝 CLI 原件和必要测试非零清单齐全。真实样本、连续使用者、预算、权限或 oracle 缺失即停止，不让 T02 执行者临时设计。

**验证与交接。** 跑文档检查和必要脚本测试，不运行 scripts/task.sh。交接 T01 commit、protocol/method/script/test 标识、真实 binary/环境、实际 Home、正反命令/raw run ID、允许路径与全部未完成项。提交按工程规范和 `scripts/check-task.sh C007-T01 <本任务开工完整提交> --staged` 核范围。

## 3. C007-M1：独立复杂模型审实验可执行性

固定 T01 完整闭包，核两组公平性、真实任务与 actor 历史、权限、质量 oracle、成本公式、预算、停止、必要脚本与合法拒绝输出。首次读者逐项走查 first-use.md，确认参数和说明都能找到，输出与错误无需即兴解释。

M1 只批准该实验准备是否可以进入实际试用，不宣布真实收益、最终质量或平台完成。发现合同/脚本/说明缺口交回 T01 作者修复，同一候选的已满足义务引用原件；改变闭包后核受影响部分。Reviewer 不审自己编写的修复。

## 4. 阶段二：C007-T02 按冻结手册执行完整任务

**入口与允许范围。** 从 M1 通过的 T01 commit 和 experiments/first-use.md 开始。只新增 experiments/runs/ 的原始记录及 review/validation/progress 索引；不改 protocol、confirmed-input、shared-method、first-use、samples、oracle、scripts 或测试。真实角色、任务目标与批准仍须来自实际参与者。

**步骤与预期。**

1. 核闭包与授权，再按冻结顺序开独立新会话。同一使用者在每组执行三项任务；开始前记 actor_id、两组 prior_uses、本组序号与实际 exposure。
2. 照手册运行各组动作和命令。所有说明请求、助手代办、换人、跨组熟悉度和活动成本入原件；不能由作者代办难点后称首次使用顺畅。
3. 在固定阶段实际关闭重开，保存旧执行者停止、新会话查找/核对/重做原件。自然返工与临时注入演练分开，超过边界不放宽方法。
4. 收齐最终候选、patch、检查与说明，分别保存真实用户接受和独立质量盲审。不用 gate、零退出或 Work 终态代质量。
5. 按冻结记录格式保存六个 run，失败/停止/未运行都有原因，usage 未知为 null。运行者检查路径引用和原件齐全，质量判断交独立审阅者。

**验收、停止与交接。** 六个 run 有原件或明确缺项；exposure 可从实际历史复算；连续使用、重开、自然/注入和助手成本可追溯。预算到限、权限不足、输入漂移、手册不完整、脚本错误或非预期退出时停止并交 T01 作者，不能改资产或重跑抹掉成本。修复任务产生新 commit/闭包，保留旧 raw；受影响记录单列并经独立复核再继续。交接实际 run ID、原始输出、质量/接受引用、缺项、允许范围和 T02 commit；文档检查及 check-task 核记录范围，无产品 Rust 测试。

## 5. C007-T03：复杂模型分析根因与范围

**输入与允许范围。** T01/M1 闭包、T02 所有 raw、质量与未完成项。只写 experiments/report.md 和 review/validation/progress 索引，不改原件、标准或使用历史。

先核实际 actor × arm 历史、换人/助手/跨组偏差，再按验证公式复算首次、实际复用及逐次累计成本。公共 P 在两组比较同口径计入、实验总投入只计一次；作者、助手、维护、接受和盲审不遗漏。解释最大重复成本的根因与消费者，每个建议给触发事实、最小行为和 oracle；没有证据可以保持当前能力。

**验收与交接。** 数值可独立复算，失败/未知不删除，质量门槛不放宽，共用样本不当 C004/C008 独立价值证据。缺连续使用、自然返工或完整盲审具体限定结论。交接 T03 commit、报告/协议/run 闭包、原审查引用、未完成项和待人决定范围；运行文档检查与 check-task。分析不授权产品实施或发布。

## 6. C007-M2：独立复杂模型核实际结果

核六次实际运行、最终内容、质量独立性、真实历史/重开/返工、完整成本、停止与因果结论，复算核心指标。M1 的准备审查在相同闭包下引用，不再次跑无关机制测试；输入或脚本变化只核影响义务。

分别判断实验执行完整性与产品价值方向；无收益可以是合格结论，缺真实任务或质量证据不能通过，未执行范围保留 not_run。问题交 T01/T02/T03 Owner，Reviewer 不审自己修复。审查见 [review.md](review.md)，原始索引见 [validation.md](validation.md)。
