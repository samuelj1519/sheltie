# C007 设计：模板先行，同副本校验

状态：`proposed`；实验 `not_run`。所有新增文件只属于采用后的实验 package 或临时目录，不成为产品协议。

## 1. 最小实验资产

```text
experiments/
  protocol.md                 组别、顺序、指标与停止规则
  templates/
    code-change/              从 spec-dev 收窄的固定方法
    document-review/          从现有写作/审查例子收窄的固定方法
  fixtures/
    pilot/                    2 项真实试用输入
    formal/                   6 项封存目标/标准；生成者不读盲审答案
  oracle/                     独立质量 checklist；只给审查者
  prompts/                    两组相同模型与差异提示
  scripts/
    validate-draft.py          同副本临时 add/show/verify 与原始证据收集
    test-validate-draft.py     手写合法/非法 fixture；脚本测试，不是产品 Rust 测试
  runs/<sample>/<arm>/         原始草稿、固定副本、命令、计时、盲审与摘要
  report.md                   产品结论与成本
```

这是预定布局，资产尚未制作。T01 才创建模板、fixtures 和脚本。模板数量固定为两份起步，不从五个提案复制所有机制。模板适配性、命令参数和 oracle 由强模型冻结；简单模型只照例填写。

## 2. 固定模板怎么设计

代码模板复用 `workbooks/spec-dev/flows/default.toml` 的独立审查、人工决定和有限返工思想，但根据试用任务选最小完整图，不要求一次性小任务携带全部规格开发节点。文档模板从 `examples/` 中已有写作+审查例子选择真实文件，明确最终文稿与检查报告。

T01 冻结每个模板的必需流程、节点输入输出、图字节、必需标准、上限和人工门槛。允许变化的只有任务说明/验收输入位置；模板关键说明不允许生成者改成「无需检查」。两组使用同一任务标准与交付对象。模板的强模型设计成本单独计入复用分析。

不能靠图证明说明有效；强模型盲审核对节点具体读取什么、产出什么、失败后往哪返工、最终结果如何取得。候选绑定与结果字段若来自 C004，只有实际实现并固定版本后才能进入模板；基于当前 release 的实验不造假字段。

## 3. 一次草稿的完整路径

1. 按样本 ID 与组别创建唯一的输出目录，生成者读取同一冻结目标/标准。脚本拒绝已经有 run 结果的路径，避免覆盖失败记录。
2. 生成草稿后，校验脚本将它复制到该 run 的私有 `confirmed-input/`，关闭生成者编辑过程。后续命令都使用这一副本；不先核一个目录再装另一个目录。
3. 脚本为本次校验创建独立临时 Home，调用固定的引擎绝对路径：`--json --home <temporary-home> workbook add <confirmed-input>`；当前 release 按 `cli-result/v2` 严格解析，确认 `ok`（若采用其他已实现版本，T01 固定该版本 DTO，不自动猜兼容），记录 `data.id/version/digest`。
4. 对同一个临时 Home 运行 `workbook show <id>@<version>` 和 `workbook verify <id>@<version>`，保存 stdout/stderr/退出码。显示图、起始输入、需要的宿主机制、完整说明与任务标准供盲审/用户查看。
5. 盲审记录结构合法之外的任务覆盖、必需检查、返工、门槛、产物可找和说明可执行性。未通过不得写成可以运行；原始失败保留。
6. 用户选择安装时，确认同一副本的引擎摘要、标准与图。正式安装单独执行 `--home <explicit-confirmed-home> workbook add <confirmed-input>`；核返回摘要完全相同。没有安装授权时停止在临时检查，不影响实验完成。

正常实验脚本只提供临时校验入口，不接受正式 Home 参数。正式安装是指南里的显式人操作，不能由 `experiment_install` 或默认参数隐式执行。临时 Home 由 `tempfile` 类机制创建，路径被记录；清理仅限脚本自己创建的目录，证据留在 package run，不清理用户 Home。

用户确认后同权限进程仍可能改私有副本；正式 add 返回摘要不同就停止，已登记到显式正式 Home 的不同版本不自动删除或覆盖。此实验不发明授权 token，不承诺同账号内对抗性封存。

## 4. 脚本与 oracle

校验脚本只编排现有 CLI、私有复制和证据保存，不读取自然语言下结论，不实现图算法、digest算法或校验规则副本。C002 已完成引擎复制与摘要，脚本仅比较引擎返回的真实摘要。

强模型在 T01 完整实现脚本的安全 Home/路径逻辑和错误处理，写手工正反 fixture：合法草稿、非法边、缺 instruction、缺必需输入、未知字段、B 组私自改图、同 ID/version 冲突、正式 Home 哨兵、源草稿改变不影响私有副本。测试 fake 仅观察进程参数与证据，不 fake 一个「结构通过」代替真实引擎。至少合法/非法装入和同副本摘要来自真实 binary。

第一次使用成果来自 T02 的 2 项 pilot，先看模板是否能用。M1 决定是否进入正式样本；T03 在看到 pilot 后冻结正式协议，pilot 成绩不混入正式比较，不为获得好结果事后改采用门槛。

## 5. 两个里程碑后的输出

M1 回答模板/脚本是否足够直观、安全，哪些首个真实样本失败及根因。M2 回答正式六项任务是否减少人工时间、是否保持标准与交付质量、强模型前置成本需要多少次复用才可能回收。

一个通过实验也只支持有限样本中的模板方向；要分发模板或改 skill，另由人采用对应产品范围。自由图生成、结构 checker、签发与运行中展开均需独立真实问题和后续候选，不作为本实验自动下一步。
