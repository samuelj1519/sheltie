## 产品目标

首批目标用户是已有本地检查、反复使用代码变更方法的仓库维护者。Sheltie 的价值假设是：方法固定后，用户在复用与中断续接中减少重复解释、过程核对和重做，保持交付质量，并保留明确的来源和批准边界。

本方案是所有后续方向共用的一轮完整任务试用。它比较认真配置的原生 agent 流程与当前 Sheltie 流程，从准备方法直到最终成果独立审阅，而不是只测 Workbook 编写、节点执行或 CLI 成功。方法作者与任务使用者可以是同一人，两类成本分别记录。

## 范围

- 使用当前 C002 完成后的真实 CLI，一份最小固定代码 Workbook 和三项真实任务，完成六个配对运行。
- 同一任务使用者在每组完成三项任务，按真实方法使用历史区分首次与复用，覆盖关闭重开和返工；至少一位未参与方法编写的首次读者实际使用。
- 原生组获得相同的方法说明、任务标准和已有宿主能力，可以认真配置 skill、提示和脚本。
- 独立审阅最终交付，记录总活动时间、墙钟时间、核对、重做、准备及维护成本；无法取得的 usage 记 `null`。
- 只制作方法、轻量记录表和必要的现有 CLI 编排；不建设原生 runner、生成器、检查平台或新的引擎字段。

实验不依赖 C004–C006 或 C008，也不自动采用其中任何产品能力。共用样本可以发现后续问题，但不能分别证明原生检查、执行者替换、导出或预检的独立收益。

## 成功判据

1. 正式运行前冻结样本、方法、组别条件、使用者及每组实际使用历史、顺序、质量 oracle、投入预算与停止条件；缺任一项不开始计时。
2. 六个运行均保留原始过程、最终交付和独立质量判断，失败、停止、未知与未运行不改写成成功。
3. 首次准备与真实复用成本可以分别计算，作者与助手投入不漏计；闭环包含实际检查、最终交付、一次真实重开和返工证据。公共方法成本在两组比较中同口径计入，实验总投入只计一次。
4. 至少一位首次读者可以按冻结材料执行，实际卡点计入成本；方法作者没有在记录之外代办。
5. 分析可以回答当前主要摩擦及下一最小范围，也允许结论为当前无需产品增量。小样本只提供方向，不证明普遍收益或统计显著性。

实施分两阶段：复杂模型完整准备方法、协议、oracle、必要脚本和测试，独立 M1 先审可执行性；简单模型或初级开发者按冻结手册运行，复杂模型分析，独立 M2 核实际结果。实验完成与产品价值成立分开判断。产品价值判据由 T01 在看结果前冻结，见 [验证](validation.md)。
