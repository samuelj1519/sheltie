# C006 规格：按需复制明确结果

状态：`proposed`；本文件定义目标行为，不描述当前已支持的命令。最终结果的选择、ArtifactRef、候选身份与条件证据只在 [C004 设计 §6 结果合同](../C004-verifiable-delegation/design.md#6-结果合同) 定义。

## 1. 用户路径

1. 用户或协调者先读取 `sheltie work result <work>`，确认这是需要的最终结果。
2. 用户需要文件副本时，显式指定既存目标父目录与本次导出标识。
3. 导出器将该结果的文件集合复制到 `<parent>/<work_id>/<request_id>/`；输出 commit 引用和实际文件位置。
4. 中断后重跑同一命令；结果相同、目标身份相同且现存文件字节相同时继续。出现冲突就停止；用户可用新的请求创建另一份副本。

目标命令：

```text
sheltie-export --sheltie <absolute-binary> --home <management-root> \
  --work <full-work-id> --to <existing-absolute-parent> --request-id <uuid>
sheltie-export --version
```

`--sheltie` 固定实际调用的引擎二进制，不依赖可变 PATH。`--work` 要完整 Work ID。`--request-id` 必填，便于首次调用前保存恢复身份。`--to` 要既存目录；不存在、含链接或与管理根重叠时，在复制前拒绝。文本结果默认给人读；`--json` 返回导出器自己的有版本响应，不使用引擎 `cli-result/v2` 冒充 Work 操作。

## 2. 导出对象

| 对象 | 处理 |
| --- | --- |
| C004 明确选择的最终 ArtifactRef | 通过引擎可信读取，核对摘要与大小后复制；保留原 ArtifactRef 与相对目标路径映射 |
| C004 条件证据报告 | 只复制结果快照明确选择的冻结报告；原始日志依旧通过结果里的指针查看 |
| 完整 commit 引用 | 写入来源清单和人读摘要，保留完整身份；不读取、复制或修改项目仓库 |
| 原始日志、中间 Attempt 输出、Workbook 冻结副本 | 不因扫描目录、猜文件名或「最后一次 Attempt」自动导出 |

首版导出整个已选最终结果集合，不增加任意路径导出或第二套 `include/exclude` 选择规则。Workbook 没有显式最终结果时，引擎按 C004 合同显示空选择，导出器在创建业务文件前拒绝；不得自行推测或仅导出空报告。

## 3. 行为规则

| ID | 规则 |
| --- | --- |
| DL-01 | 只允许已经满足 C004 最终结果条件的 Work。引擎与导出器版本不一致、结果格式不支持或结果摘要不符时，目标目录不得出现业务文件。 |
| DL-02 | 授权仅对本次命令指定的既存父目录有效；后续命令重新显式给出。导出请求保存父目录及请求目录的设备号、inode 与路径用于恢复核对。 |
| DL-03 | 导出器在目标目录保存不可变的 `request.json`，包含结果快照、请求标识、版本、目录身份与完整文件清单。请求身份的作用域是父目录身份、完整 Work ID 与 request-id；同一请求目录的参数或结果不同就冲突，不改旧请求。改变父目录或 Work 是另一份导出，流程要求使用新 request-id，但没有全局索引强制 UUID 不复用。 |
| DL-04 | 目标文件缺失时新增；已经存在且实际字节与期望相同则跳过；字节不同、类型不对或身份异常时停止。禁止覆盖、原地截断或删除已有成果。 |
| DL-05 | 复制从引擎可信读取的实际字节完成。导出器独立核对大小与 sha256；不能仅信源路径、组件自报或清单。 |
| DL-06 | 每个新文件在同一父目录句柄下独占创建临时文件、同步、原子不替换发布、同步目录；清单在所有成果读回相符后最后发布。 |
| DL-07 | 请求内路径都是受校验的相对路径；每段相对受限目录句柄打开，不跟随符号链接。现存文件硬链接数不为 1 时拒绝，不能通过根外链接复用字节。 |
| DL-08 | 中断恢复逐个读取现存文件并核对；`manifest.json` 存在也不免除核对。只清理本请求有归属证明的临时文件。 |
| DL-09 | 导出不写 Store、不增添终态例外，不提交送达回执，也不维护导出后文件变化。清单只证明这次完成核对时的结果。 |
| DL-10 | 仅 `aarch64-apple-darwin` 提供首版导出；平台缺乏实测的受限打开与原子不替换能力时阻断实施，不降级到先检查后覆盖。 |

导出器返回四种可区分结果：完成、可重试的中断、目标或请求冲突、确定性拒绝。初级实现者只实现 T01 冻结的错误枚举，不根据 stderr 文案自行猜分支。命令失败输出已完成项与剩余项的事实，但不把部分复制称为交付完成。

## 4. 权限与限制

引擎 `sheltie` 仍只写管理根。导出器不依赖 `sheltie-runtime`，不直接读写 Store；通过只读引擎命令取字节，不直接执行管理根写入；引擎只读接口的控制文件维护按公开合同识别。目标目录授权不包括宿主配置、shell 配置、skill 安装与其他请求目录。

同一 OS 账户不是独立真人认证边界。句柄约束能防止路径替换将写入带到根外，不能阻止同权限外部进程在导出完成后编辑或移动副本。副本可以编辑；不建设持续观测或自动修复机制。

## 5. 采用后的文档变化

采用时更新外围组件的架构、导出合同、操作指南与平台发布说明。宪章、终态规则、存储 schema 与引擎 `self` 组无需增加例外。新二进制由显式安装命令或发行归档交付；不修改宿主配置，不把版本不匹配的两份二进制自动修成可用。
