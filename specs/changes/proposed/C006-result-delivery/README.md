# C006：按需导出最终成果

状态：`proposed`
目标版本：`待采用时指定`（独立导出二进制与引擎采用相同版本）
兼容性：新增外围二进制；不改 Work 终态、Store schema 或 `self` 命令；仅 `aarch64-apple-darwin`
基线：`17a1647758ceea5ebf637610ab2cdf91589c5218`
Owner：`待采用时指定`
权威性：候选方案；任务均为 `todo`，实现与实验均为 `not_run`

## 产品目标

用户已经能通过 C004 的 `work result` 找到明确的最终成果。用户需要可编辑的文件副本时，再将选定结果可靠地复制到自己授权的位置。代码成果首先交付已验证的完整 commit 引用；导出不会替用户复制仓库、合并、提交或部署。

只读结果查看属于 [C004](../C004-verifiable-delegation/README.md)。本方案只补文件复制的缺口：复制中断后能继续，已有不同字节时停止，写入范围受授权目录约束。

## 范围

- 一个独立 Cargo 包与二进制 `sheltie-export`，通过同版本 `sheltie` 的只读公开接口取得最终结果与 Artifact 字节。
- 显式命令授权一个已经存在的目标父目录；在其下创建本 Work、本次请求专用的新目录。
- 冻结本次导出请求，逐文件复制并读回；相同字节不重写，不同字节冲突停止；来源清单最后发布。
- 导出自己的请求与清单留在目标目录，不反向推进 Work，不写管理根。
- 首版只支持当前发布平台；先显式独立安装导出器，不改引擎 `self install/update/rollback`。

## 成功判据

1. 文档类任务交付明确选择的 Artifact 副本；代码类任务清楚展示完整 commit 引用及其检查报告，不能将 commit 伪装成管理根里的代码文件。
2. 成功输出实际目标位置、结果摘要与来源清单；任意中断后用同一请求可以继续，且每个现存文件仍按实际字节核对。
3. 链接、目标竞争、父目录替换与不同字节冲突均不导致覆盖或根外写入；根外哨兵字节与权限不变。
4. 导出前后 Work、Attempt、门槛与请求历史不因导出变化；引擎只读查询允许的 Store 控制文件维护按现有合同单独识别。
5. 一次真实任务探针证明用户确实需要副本，并分别报告找结果与复制结果所花人工时间；探针失败不由文件安全测试的通过替代。

## 采用条件与依赖

人先采用 C004 核心闭环并取得稳定的最终结果读取合同；本方案依赖该合同，不维护缺少 C004 时的另一套结果选择方法。随后由人判断副本导出是否值得实施，并指定 release 与 Owner。C002 的受限句柄和原子发布实现是技术参考，安装正确性沿用既有引擎能力。C005、C007、C008 不构成依赖。

采用只授权本 plan 的实现与验证；发布、安装到真实用户目录、push 和对外分发各沿既有治理入口。首版不提供长期送达状态、回执写回、结果根重定向、自动覆盖或后台同步。
