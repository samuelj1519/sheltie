# C006 验证

Candidate: `none`

状态：proposal 阶段。全部实验为 `not_run`。本文件先固定实验口径，避免事后调整指标。依赖就绪的实验已拆到 [C008](../C008-dependency-readiness/validation.md)。

## 1. 要回答的问题

1. **机制是否正确：** 交付请求、回执、恢复、目标根写入合同与终态例外是否按承诺工作。
2. **用户价值：** 用户是否不再需要自己寻找、复制和核对成果。

机制正确不等于有用户价值（GF-19），分开报告。

## 2. 探针

- 先测基线：用户在真实 Work 上按现状从管理根找到、复制并核对交付文件；
- 任务样本自备，不借用 C004 的样本，不以 C004 采用为前提；样本在实验开始前写定；
- 导出组件先用外部脚本实现 design.md §3 的协议，只复制明确授权的文件；送达记录标为「外部回填」，不改产品代码；
- 在临时目标根中演练中断、目标编辑与重复调用；
- 三种目标位置各至少一次：默认位置、项目目录内、自定义目录。

| 指标 | 口径 |
| --- | --- |
| 找到成果的时间 | 从 Work 结束到用户打开需要的文件 |
| 复制与核对的人工分钟 | 用户为确认「拿到的就是流程完成时的那一版」花的时间 |
| 送达错误 | 送错版本、漏送、覆盖了用户文件的次数 |

## 3. 失败路径测试（与用户价值分开报告）

采用并实现后执行。以下场景都可以直接用程序测试，不需要调用模型。进程被杀的窗口分别覆盖文件写入中、来源清单写入中、回执提交前后。

| 场景 | 应观察到 | 不能出现 |
| --- | --- | --- |
| 文件已写入，回执前进程退出 | 恢复时按请求逐文件核对一致，补记回执 | 重新覆盖写入 |
| 部分文件写入后中断，来源清单不存在 | 已写且一致的不重写，只补写缺失部分，再写来源清单 | 已写部分被重写；因清单缺失判为未写 |
| 来源清单仍在，但某个目标文件已被改 | 送达冲突，交给人 | 按清单补记回执；覆盖用户修改 |
| 回执提交后目标文件立即被改 | 回执保持送达时摘要；新增「交付副本被修改」观测 | 回执被改写 |
| 回执重复提交 | 第二次被拒绝 | 两份回执 |
| 回执中的实际摘要与请求不符 | 拒绝，不记为已送达 | 按回执自述记为已送达 |
| 目标文件缺失或已被改，组件仍提交与请求一致的摘要 | `sheltie` 读回摘要不符，拒绝 | 按组件陈述记为已送达 |
| 目标路径某段在回执核对时是符号链接 | `sheltie` 读回拒绝，不记为已送达 | 跟随链接读到根外文件并记为已送达 |
| 终点 Attempt 成功但有未批准门槛 | 不生成交付请求 | 提前交付 |
| 未采用 C004 时的交付包 | 用语为「流程完成后的产物副本」 | 显示「候选已经过接收出口」或质量结论 |
| 目标路径某段是符号链接（含检查后替换） | 拒绝写入，送达失败，根外哨兵字节与权限不变 | 写到目标根之外 |
| 目标根被替换为另一目录 | 身份核对失败，拒绝 | 写入新目录 |
| 目标根等于、包含或位于管理根内 | 授权与导出时都拒绝 | 改写 Store 文件 |
| 导出清单含 `..`、绝对路径或空段 | 拒绝 | 越界写入 |
| 目标文件存在其他硬链接 | 原子替换目录项，链接另一端内容不变 | 写穿到链接另一端 |
| 目标根里有清单之外的文件 | 保持不动 | 被删除或覆盖 |
| 覆盖策略为 `refuse`，目标已有同名不同摘要文件 | 送达冲突 | 静默覆盖 |
| `refuse`：检查后、改名前另一进程创建同名文件 | 「不替换」改名失败，送达冲突，对方文件字节不变 | 覆盖对方文件 |
| `replace-own-unmodified`：检查后、交换前用户改了旧文件 | 交换后读到换出字节与旧回执不符，换回原状，送达冲突 | 用户修改丢失 |
| 平台不提供「不替换」改名或原子交换 | 不提供导出或只提供 `refuse` | 退化为先检查再普通改名 |
| 终态 Work 追加送达记录 | 成功，执行结果不变 | 被拒绝，或改写了执行结果或接收事实 |
| 终态 Work 上的其他写操作 | 仍被拒绝 | 借送达例外写入 |
| 协调者自报已复制 | 记为自报 | 显示为已送达 |
| 交付副本被删除 | 记为目标副本缺失，可重新导出 | 历史送达记录被改写 |
| 目标根暂时不可访问 | 记为不可访问 | 当作已删除 |
| 管理根唯一原件缺失 | `STORE_CORRUPT` | 用交付副本充当原件 |
| 修改结果根 | 形成新绑定版本，旧记录按旧绑定解析 | 旧记录指向新位置 |
| 导出二进制运行全过程 | 管理根只被读取 | 导出二进制直接写 Store |

目标根写入合同的场景在每个支持的平台上分别执行。
