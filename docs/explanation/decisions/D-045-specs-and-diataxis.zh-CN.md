# D-045：分离 spec-driven 依据与 Diátaxis 技术文档

[English](D-045-specs-and-diataxis.md) | 简体中文

状态：`accepted`
日期：2026-10-05
关联：用户要求以当前已完成功能重构文档；细化 [D-032](D-032-use-change-packages.zh-CN.md) 的文档职责

## 背景

过程产物清理后，specs 仍同时保存行为约束、使用步骤、参考索引、源码解释和外部阅读线索。维护者需要明确规范与采用范围，使用者和源码读者需要按自己的目标阅读；共享一个入口容易把两种需要混在一起。

## 选择

specs 保存宪章、产品规格、架构约束、精确合同、工程规则、路线图与未完成 change。实现定位、验收和发布记录归 docs/reference，ADR 归 docs/explanation/decisions，已关闭变更归 docs/history/changes；治理工具继续核原资格，不要求历史材料留在 specs。docs 按 [Diátaxis](https://diataxis.fr/) 的 tutorials、how-to、reference、explanation 组织长期技术文档；混合正文按用途拆分。历史档案是追溯入口，放在四类当前读者材料之外；当前主题解释不要求读者按迭代顺序还原设计。

当前代码用于核对已实现事实，独立验收与发布记录用于限定已验证／已发布结论。宪章中宿主权限与就绪的泛化表述按已有 GF-20／GF-22 边界澄清，不引入权限求值、隔离或探针机制。代码不自动取代规范；差异需记录，修实现或明确采用上游变更。未来方向不写为当前可用能力。

字段、命令、错误、限额与持久格式仍只在 specs/contracts 定义。docs/reference 提供已实现关系和查阅入口，链接精确合同，不手工复制完整定义。架构的约束在 specs，因果解释和源码导航在 docs；重要取舍的正式理由仍保留于 ADR。

## 备选与后果

- 只移动文件会留下快速开始兼真实任务手册、架构兼类型签名与解释等混合职责，无法满足不同阅读目的。
- 复制合同到 docs 会形成两个易漂移的精确来源，因此保持一个规范来源和读者入口。
- 将实现全部写成已验收或已发布会丢失环境、费用和公平对照边界，因此分别维护实现基线与验收记录。

根 README 指向 docs 供学习使用，AGENTS 指向 specs 供行为修改，再按任务读取 docs。迁移同时修复引用、生成输入和检查消费者；历史快照内的路径保持。

## 确认方式

新读者应能找到教程、目标操作、产品参考和原理解释；维护者应能找到当前能力、精确规则、未采用方向与验收边界。机械检查核链接、版本、ADR、生命周期和合同消费者；真实 CLI 核新增操作路径。结构或命令通过不代替首次读者实际体验。
