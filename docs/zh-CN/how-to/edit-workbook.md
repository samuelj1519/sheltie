# 用画布编辑 Workbook 并取得新副本

[English](../../en/how-to/edit-workbook.md) | 简体中文

用于可视化新建或修改一份方法。作者工具是从源码目录运行的本地网页，需要 Node.js ≥ 22 和当前源码的可信引擎。工具编辑浏览器草稿、下载新 ZIP；不会覆盖作者目录或运行 Work。

## 1. 启动本地工具

先按[构建指南](build-from-source.md)取得 `engine_binary`。在仓库根安装工具自身依赖，命令成功后启动：

```bash
npm --prefix tools/workbook-editor ci --ignore-scripts --no-audit --no-fund
node tools/workbook-editor/server.mjs --sheltie "$engine_binary" --port 4311
```

打开打印的实际 `http://127.0.0.1:port`。不能替换成 `localhost`，Host 校验会拒绝。端口占用时停止该调用，选择可用端口重启；Ctrl+C 停止自己的服务。

## 2. 打开并编辑草稿

选择「新建方法」「打开目录」，或展开左侧样例选择「代码变更」「规格开发」。打开 ZIP 前先解压到独立目录，工具不直接导入 ZIP。已有同 ID、同版本的已装方法需要修改时，在草稿中创建新版本。

编辑方法 ID、版本和 Flow；增加 Node，写说明与输入输出，指定 entry，再增加显式 Edge。选已有端点会定位已有边，自环或重复端点编辑被拒绝。输入来源另外选择，连线不自动添加绑定。

选择 Node 后通过「输入 N／输出 N」页签查看资料，用搜索定位，再点击单项编辑名称、来源或输出路径。高级设置处理 `required`、`result`、大小与额度、宿主资源声明；不修改的字段保持原声明。human 执行者不设置 tier。

## 3. 选择输入资料

展开「＋ 添加资料」，在统一选择或输入框中多选前置输出，或沿用前置输入的原来源。自定义名称只需在本步骤内唯一；同名冲突按提示改名，不能通过改名把旧来源替换成另一份资料。

已有来源的勾选表示已经使用；移除从已选列表逐项操作，同来源的其他别名保持。未确认的待添加选择在折叠或切换页签时保留，但仍需按「添加所选资料」写入草稿。

输入文件位置或 URL 并按 Enter，会建立方法内的固定参考文本。工具不读取该宿主位置或访问网址；执行者根据方法说明取得实际资料。沿用前置输入同样只是沿用 `from`，不是读取前次 Attempt 的冻结输入副本。

## 4. 查看图与定位问题

用主流程视图看主干，完整连线视图核所有边；聚焦 Node 查看邻接边。隐藏边仍可从「全部连线」列表选择并定位，实际 from/to/kind 与属性一致。拖动、平移、缩放和「整理布局」只改视图，不改方法字节。

点击「检查结构」，按返回的文件、Node、字段和规则修草稿。绿色结果只属于当次完整文件集合。未知字段仍被引擎拒绝；不能用表单把它们清洗掉。无法解析或不能表达的文档保留原 bytes，并拒绝相关编辑。

## 5. 保存、重新打开与装入

关闭、刷新或换草稿前点击「保存新副本 ZIP」。保存会重新检查当前集合，成功后解压到新的作者目录。用「打开目录」重新打开核内容；确定交付版本后，按[方法管理](manage-workbooks.md)执行 CLI add/show/verify，再试运行必要路径。

草稿只在当前页面内存，localStorage 仅保存布局。结构失败时 ZIP 不会成功生成；不要依靠刷新恢复未保存内容。窄屏可在导航／属性面板内点击「关闭」，或按 Esc 返回画布。

输入限额、HTTP 拒绝与进程清理见[工具参考](../reference/workbook-editor.md)。结构通过不证明内容质量、实际流程完成或用户接受；原理见[作者工具设计](../explanation/workbook-editor.md)。
