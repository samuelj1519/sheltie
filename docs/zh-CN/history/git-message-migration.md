# Git 提交信息迁移参考

[English](../../en/history/git-message-migration.md) | 简体中文

本次经授权的英文默认迁移翻译了 260 个可达本地提交的信息。每个提交的文件树、所有非父提交头字段（包括作者、提交者和时间）、父提交顺序与拓扑，以及机器 trailer 均保持。父提交 ID 和提交信息中可解析的提交引用按[新旧映射](../../en/history/git-message-migration.tsv)更新。

映射保留原身份供追溯。历史文件树和原始证据未被翻译或改写；当前文档与工具引用使用映射后的本地 ID，冻结历史文件内的原 ID 可查映射解析。实物 SHA256 保持不变。

最初的本地迁移通过一次带旧值守卫的事务更新分支、轻量发布与审查 tag、归档引用及 stash，共 43 个引用，并保留当时观察到的远端身份及原映射 blob 字节。之后获授权的项目发布仅替换 main 分支，当时保留原发布 tag。

后续获授权的远端清理仅保留 `main` 分支，并将 `v0.1.0` 和 `v0.2.0` 指向其历史上的对应提交。远端旧候选分支与 `v0.1.0-rc` tag 已删除。发布记录的 Release commit 标识当前 tag 目标，原发布提交保留用于追溯；两者源码树完全相同。历史发布资产、校验和及已记录的工作流身份保持原样，旧运行不改记为针对新提交的重跑。本次清理不创建新的产品 Release。

历史查询先在映射首列查原 ID，取第二列执行 `git show <mapped-id>:<path>` 或 `git archive <mapped-id>`。映射提交保存完全相同的原文件树，其中的历史中文仍保留。参见[历史查询](../how-to/maintain-docs.md#查阅历史原件)。

后续仓库重建移除旧 GitHub PR 引用与工作流运行。本地归档引用、reflog 以及 `main` 历史之外的 Git 对象已清理，不保留原历史备份。映射中的旧提交 ID 仅用于追溯；历史源码与证据从对应的映射提交读取。`main` 中的固定快照仍然可用。

新远端仅包含 `main` 及其两个发布 tag。发布附件按原字节恢复，Wiki 从已提交源码重新生成。重建后的 GitHub 记录具有新的身份，不复现原工作流运行，也不构成新的产品验收。

[C012 历史参考](changes/C012-english-default/README.md)指向固定 Git 快照中的完整采用任务、精确对象核验、应用记录与最终检查；本次范围不扩大历史产品验收或发布证据。
