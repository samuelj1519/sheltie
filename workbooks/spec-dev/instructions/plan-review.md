这一步由人完成。你要判断规格和方案能不能开工。这是整个流程里唯一需要人拍板的地方，后面的实现、验证、审查、修复都由 agent 自动进行，直到交付。

## 读什么

1. `spec`：需求规格。先看「目标」和「验收标准」是不是你想要的；再看「开放问题」，每个问题你都要给答案。
2. `plan`：技术方案。重点看「改法」有没有明显走偏，「门禁」命令对不对。
3. `tasks`：任务清单。抽查两三个任务，看是不是够小（填几个函数体的量）、「要变绿的测试」名字是否能看出在验什么。

不需要逐字审。规格与方案的细节错误会在实现和审查阶段被 agent 自己发现。你把关的是方向。

## 写什么

写一份 `decision.md`。**第一行只写下面三个词之一**，协调者按它选下一步：

- `通过`：开工。下一步是强模型搭骨架（类型、签名、禁用的测试），之后才是逐任务实现。
- `修改规格`：回到写规格那一步。
- `修改方案`：回到写方案那一步。

第一行之后写你的意见，每条一行，能定位到规格或方案的哪一节。开放问题的答案也写在这里。选「通过」时可以附带小意见，实现阶段会参考，但不会再回来找你确认。

## 写到哪

把 `decision.md` 写到任务书「输出要求」里 `decision` 对应的路径，然后运行任务书末尾给出的 `sheltie attempt submit` 命令提交。
