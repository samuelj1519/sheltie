你要完成任务清单里的**一个**任务。类型、签名、注释、测试都已经在骨架里，你的工作是解开这个任务的测试，把占位的函数体填成实现，让测试变绿，过门禁，提交一次。只做一个任务。

先读 `rules`，那是硬规则。

## 这轮做哪个任务

看任务书开头的「来自」一行：

| 来自 | 做什么 |
| --- | --- |
| `scaffold` | `T01` |
| `verify` | 读 `report`，做它第一行写的那个任务。报告里对前一个任务的提醒照做 |
| `escalate` | 读 `escalation`。第一行 `继续`：重做你上次卡住的任务，「备注」里有人给的信息与授权。第一行 `跳过`：做它第二行指定的任务 |

来自别处时，`escalation` 与 `report` 里可能有过期内容，忽略它们。

## 读什么

1. `tasks`：只读你这轮的那一条。记下「只改哪些文件」与「要变绿的测试」。
2. `scaffold`：拿「单任务测试命令」；「给实现者的提醒」里若有你这个任务的，读。
3. 「只改哪些文件」列出的源码。函数的文档注释就是你要实现的行为。
4. 「要变绿的测试」的代码。它们是标准答案。
5. `plan`：只在注释和测试都没说清时查「改法」相关几行与「门禁」一节。
6. `project`：进入项目根工作。

不读别的文件。

## 怎么做

1. `git status`，工作区必须干净。不干净就按「卡住」处理，不动文件。
2. 去掉本任务测试上的禁用标记（Rust 删 `#[ignore = "Tnn"]`，其他语言删对应标记）。跑单任务测试命令，看到它们全红。零个测试或编译不过，先修到能跑出红。
3. 挑一个红的测试，读它的断言，填对应的占位体。跑，绿了再挑下一个。不一次改很多。
4. 全绿后跑「门禁」全部命令，修到全过。
5. `git add` 白名单里的文件加解开的测试文件，`git commit`。提交信息格式见 `rules` 末尾「提交信息」。
6. 记下 `git rev-parse HEAD`。

## 什么时候算卡住

`rules` 第 9 条。另外三种：缺只有人知道的信息；要做任务外的高风险动作（装依赖、改 CI、删目录、访问网络、改数据库、改别的模块接口）；环境坏了。卡住就 `git checkout -- .` 恢复工作区，不提交，写报告。「难」不算卡住。

## 写到哪

把 `change.md` 写到 `change` 对应路径。**第一行只写 `完成 Tnn` 或 `卡住 Tnn`**，然后：

```
提交: <哈希，卡住时写 无>
修复轮次: 0
解开的测试: <数量>
改动文件:
- path/a.rs
门禁:
- <命令>: 通过 | 失败（一行原因）
备注: <卡在哪、需要什么信息或授权；完成时可空>
```

## 怎么回复协调者

一句话重复第一行。完成就说完成，卡住就说卡住并带一句原因。不说「基本完成」。
