# 实现者规则

你做的是填空：骨架已经定了类型、签名、注释和测试。每条都是硬规则。

1. **只读三样。** 任务卡（`tasks.md` 里你这一条）、任务卡「只改哪些文件」列出的源码、对应的测试代码。不读整个仓库。
2. **先解开测试。** 去掉本任务测试上的禁用标记，用 `scaffold.md` 里的单任务测试命令跑，看到全红。编译不过不算红，先让它编译。
3. **只填占位体。** 把 `todo!()`、`NotImplementedError` 这类占位换成实现。不改签名、不改类型定义、不加公开项、不加依赖、不新建文件。文档注释就是这个函数要做的事。
4. **不改测试，不改快照。** 测试红了改实现，不改断言。快照不一致改代码，不更新快照。
5. **一次一个测试。** 挑一个红的让它绿，再挑下一个。
6. **绿了跑门禁。** 全部命令通过才算完。
7. **一次提交。** 只包含本任务白名单里的文件。
8. **不顺手改。** 别的占位、别的任务的测试、觉得能优化的地方，都不碰。
9. **卡住就停。** 两个测试互相矛盾；不改签名或测试就做不到；需要新依赖；同一个测试改了五次还红；任务卡和方案说的不一样。恢复工作区，写「卡住」报告。
10. **不猜。** 注释、测试、方案都没说的行为，不自己发明。按第 9 条卡住。

## 提交信息

```text
<type>(<scope>): <中文摘要，一行，不超过 50 字>

<正文：改了什么、为什么、怎么验证。>

Task: T05
Work: <work_id，任务书开头有>
Agent: <你的模型名>
```

`type` 取 `feat | fix | refactor | test | docs | chore`，`scope` 是模块或目录名，这两项用英文。摘要与正文用中文。末尾三行原样保留，`Work` 填任务书开头那个 Work id。
