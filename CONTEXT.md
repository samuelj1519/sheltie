# Sheltie domain vocabulary

English | [简体中文](CONTEXT.zh-CN.md)

Shared language for the repository. Each concept has one name, used consistently in documentation and code.

## Naming

| Name | Meaning |
| --- | --- |
| Sheltie / `sheltie` | Product, repository, and binary name |
| `sheltie-*` | Cargo crate names only: `sheltie-core`, `sheltie-runtime`, `sheltie-cli`, and external `sheltie-export` |
| `workbook/v1`, `flow/v1`, `cli-result/v4`, `work-result/v1` | Current target format versions, without a product prefix; `cli-result/v1` and `cli-result/v2` belong to historical v0.1.0 and v0.2.0 respectively |
| `workbook.toml` | Workbook manifest filename |
| `SHELTIE_HOME` | Management-root environment variable; defaults to `~/.sheltie` |

## Core terms

| Term | Definition |
| --- | --- |
| Workbook | A method written and frozen by a person: a directory containing a manifest, Flows, and instructions. The only term for a business method |
| Flow | One runnable graph within a Workbook |
| Node | One step in the graph, with instructions, inputs, outputs, an executor, and an optional gate |
| Edge | An explicit directed edge between nodes: `main / back / branch / re_review` |
| Work | One run of a specific Workbook version. A `work_id`, such as `2026-09-24-001-article-draft`, combines the UTC date, daily sequence, and name |
| Occurrence | The nth arrival at a node in a Work, written `node#n` |
| Attempt | One execution attempt within an Occurrence, written `node#n.number`. Records execution and administrative revocation: `running / succeeded / failed / superseded` |
| Brief | A file generated for an Attempt: the original instructions plus bound input paths and output requirements |
| Status card | A compact progress view generated by the engine; pointers only, without historical bodies |
| Legal next actions (`next`) | Operations the engine determines the coordinator may currently invoke |
| Gate | A node property requiring human approval after a successful Attempt before leaving the node |
| Tier | A node label, `strong` or `standard`, helping the coordinator choose a model; the engine does not act on it |
| Artifact | An Attempt output frozen by sha256 on submission |
| Draft output | A declared output location for a running Attempt; the path does not prove that a file exists or is sealed |
| Result | Frozen inputs and sealed outputs explicitly selected by a successful terminal node; references bind to that specific terminal Attempt |
| Resource | A file under a Workbook's `resources/`, bound through `resource.<path>`. Frozen with the version, without host installation |
| Host resource | A skill, named subagent, or MCP requiring installation in the host. Declared by `kind + name` in `requires`; the engine lists it without installing it |
| Frozen copy | The Workbook directory copied to `works/<work_id>/workbook/` by `work start`; subsequent operations in this Work read only that copy |
| Coordinator | An agent or person who reads the Workbook, delegates work, interprets responses, and chooses a route from `next` |
| Worker | An agent or person who transforms inputs into outputs according to a brief |
| Engine | The `sheltie` binary. Records state, generates briefs, computes `next`, and enforces gates without judging content. `self` manages the engine and `workbook` manages methods; both write only under `~/.sheltie` |
| Export | A new editable directory published by the external tool after verifying explicit final results, under an authorized parent. Does not write back into the engine or become a second result authority |
| Package | A Cargo package or external dependency; never a business entity |

## Repository status

The current release, active/proposed changes, and implementation entry points are defined only in [specs/README.md](specs/README.md).

An Attempt's `number` suffix is its creation sequence within the Occurrence, starting at 0. Only `failed` counts toward failures; `superseded` does not consume `max_retries`. Replacement revokes the previous qualification and starts a new Attempt in one write operation, at most once per Occurrence. It neither stops the previous process nor proves host isolation.
